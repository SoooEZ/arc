# Maintaining and extending ARC

ARC remains one React application and one Java application. The HTTP paths, graph JSON, ARC Script, published versions, database migrations, and execution semantics remain the public contracts. Start with [the graph contract](architecture.md) and [API reference](api.md) before changing them.

For AI-assisted changes, [the project guidance and Skills](ai-quality.md) turn these boundaries into implementation, refactoring and review workflows. Their [pinned upstream references](ai-sources.md) document the ideas selected and adapted to ARC.

Read the applicable [review lessons](review-lessons.md) before changing a boundary. They connect failures found in earlier reviews to preventive rules and existing behavior tests; dated reports retain the original evidence.

## Backend boundaries

| Package | Responsibility | Extension point |
| --- | --- | --- |
| `api` | HTTP binding, response status, error translation, request limits | Controllers call application services; no SQL. `PageParameters` binds paging; `RequestLimitFilter` caps every request body before any other filter; `ApiCors` owns the CORS policy, whose origin the filter's `413` states |
| `rule` | Draft commands, publication transactions, definition checks, execution orchestration | `RuleRepository` separates storage; definition and execution services are separate; `RuleTemplates` holds the graphs new rules start from and `RuleSamples` seeds the samples |
| `engine` | Narrow dependency ports and shared identifier, value-text and limit policies | `RuleResolver`, `SourceReader`, `MemoizingRuleResolver`, `Identifiers`, `InputTypes`, `Limits`, `ValueText` |
| `engine.expression` | Expression parsing, evaluation, bounded values and function capabilities | `Expressions` and `Functions`; POI stays behind `ExcelFunctionAdapter`, with `ExcelText` owning POI's formatting and `ExcelMatchingWork` bounding the work of its wildcard and number patterns |
| `engine.script` | ARC Script scanning, document/node grammar, canonical rendering and statement locations | `ArcScript` owns whole-graph and single-node build/render operations |
| `engine.graph` | Topological order, cycle location and branch-sensitive available variables | Read-only `GraphPlan`; topology, scopes and Boolean conditions remain internal |
| `engine.validation` | Draft shape, executable graph checks and editor diagnostics | `Validator` coordinates shared shape and node checks; `Problems` collects located problems once |
| `engine.execution` | Graph execution sessions, joins, traces and parameter resolution | `Engine` creates a `GraphExecution`; nested calls share execution limits |
| `source` | Version commands, static binding checks, typed reads and provider registry | `SourceService` owns writes; `SourceExecutionService` dispatches reads, and its request `Session` implements `SourceReader`; `SourceVersions` keeps the frozen pinned versions that reads and static checks share |
| `source.http`, `source.lookup` | Provider-specific validation and fetching | `SourceAdapter` implementations registered by `SourceAdapters`; `HttpDestinationPolicy` and `BlockedAddresses` own HTTP destinations |
| `persistence` | JDBC, row locks, JSONB serialization, repository implementations, storage error translation | `JdbcRuleRepository`, `JdbcSourceRepository`, `JsonCodec`; shared `CatalogPages` paging and `StoredText` text policy |
| `model`, `error` | Portable records, node kinds (`NodeKind`, `Handles`), page requests and structured application errors with typed kinds | No Spring, JDBC, or HTTP imports |

Dependencies point from HTTP into application services, and from application services into the engine and repository interfaces. JDBC implementations depend on those interfaces. The engine does not depend on controllers, JDBC, or source application services. Spring constructor injection assembles the implementations; its component annotations in the engine are intentional, so this is not a framework-free core.

Catalog/history consumers use bounded summary pages; one selected rule/version/source is fetched on demand. `model.PageRequest` owns the paging contract for every catalog and history endpoint: omitted offset and limit read from 0 with 20 items, the limit is 1–100, and the search is trimmed and then at most 200 characters. Controllers bind it through `PageParameters`, which reports bounds as the usual `422`. `persistence.CatalogPages` runs the count and page statements. Summary queries choose the page's rows before reading JSONB, so per-row JSONB work never scales with every matching row. Full-list repository/API methods remain only for compatibility. Keep summary and detail types distinct; a summary cannot stand in for an editable definition. Searches belong on the server, and async detail responses retain selection identity.

The Rule library owns browsing and pagination; the collapsible navigation does not duplicate its catalog. Card previews load only for the mounted page and cancel on page/search changes. A preview represents every actual node and valid connection, including fan-out and joins. Small graphs show labels; complex graphs show an overview with a direct route to the full canvas. Preview layout is local presentation data and never changes saved positions. Library search waits 250 ms after typing (`searchDelayMs`) and keeps the shown cards while the next page loads. Card previews are cached by rule incarnation (ID and creation time) and revision (about two pages), so a rule created again under a deleted ID never shows the old graph. Saving or creating a rule marks the library stale; it reloads the same page when the library is shown again. No other view receives the library's items: the editor reads a referenced rule's name itself, from its summary by ID (`GET /rule-summaries/{id}`, without the draft), and the playground pages its own published catalog, so a name or release is never a stale hint.

Execution trace collection is optional and retains complete prefix steps within 256 KiB of UTF-8 JSON. Execution step accounting is independent of retained trace length. Runtime deadline exhaustion is `504`. The deadline and exhausted shared budgets (`ArcException.Kind.DEADLINE`/`LIMIT`) bypass source/expression fallbacks and Transform/Switch context, and remain attached to node locations. `timing` measures server preparation/execution; the UI separately measures request round-trip latency including JSON parsing.

The root `engine` package contains shared contracts, not feature orchestration. `Identifiers.isValid` owns identifier syntax and reserved words, `Identifiers.isResourceId` the rule/source ID slug used by rule and source creation, Reference pins, source pins and `@id:version` calls, and `Identifiers.CASE_ID_SYNTAX` the Switch case-ID syntax. `InputTypes.Type` is the one vocabulary of declared types: which values a type accepts and whether it is scalar (as a source parameter must be) are exhaustive switches, so a new type does not compile until it decides both. `InputTypes.check` applies it, and `InputTypes.NAMES` lists its names for draft shape and the ARC Script grammar. A source binding's error policy is `SourceBinding.OnError` and an execution's read status `Parameters.Read.Status`; their JSON is the constant's name. `Limits` owns the size limits and execution budgets that several components enforce or produce; messages state a limit from its constant (`Limits.format` for grouped numbers such as "2,000", `Limits.formatBytes` for byte sizes such as "1 MiB"). `ValueBounds` owns the value bounds every number, text and collection must satisfy (`number`, `bounded`, `typeOf`), so `ValueText` and `InputTypes` bound values without depending on the expression package; `Expressions.number` and `Expressions.bounded` delegate to it. `ExecutionDeadline.within` is the one owner of "check, work, check": definition reads, source reads and evaluations run inside it, so no work starts after expiry and a late value is discarded. `ValueText` owns canonical scalar text: `text` is the `$TO_STRING` conversion, used for joined, searched and sent text such as HTTP source parameters, and `key` gives equal numbers one text form (`1E+3`, `1000.0` → `1000`) for paths, indexes and lookup keys. `ArcException.Kind` separates recoverable value errors (`INVALID`, `NOT_AVAILABLE`) from `LIMIT` and `DEADLINE`; fallbacks check `recoverable()`, never an HTTP status or message text, and a new request-wide budget throws `ArcException.limit`. Expressions, ARC Script declarations and source providers can use these policies without depending on graph validation. Required, missing, explicit-null and default handling remain with the caller. Keep implementation helpers package-private within their feature; moving files should not turn every helper into a public API.

`RuleService` owns create/save/publish/delete transaction boundaries. A publish must lock the draft, check its revision, hold the rules the draft calls (`RuleRepository.lockCallees`, `FOR KEY SHARE`), validate pinned dependencies, and insert the version in one transaction; saves and creates hold their callees the same way before writing. A deletion locks its rule `FOR UPDATE` (`lockForDeletion`), which waits for every writer of a caller, checks the optional revision the client read, and then scans for callers with `Validator.calledRuleIds`, so a concurrent caller is either seen or refused. Writers lock their own rule `FOR NO KEY UPDATE`, which is compatible with the callers' `KEY SHARE` locks, so two drafts that pin each other cannot deadlock. Revisions come from the `rule_revisions` sequence, so a re-created rule never repeats a revision an open editor may hold. Repository replacements must preserve these guarantees, including `409` conflicts. Source revisions use the same application transaction boundary. Never move a write outside that boundary just to shorten a service method. Repositories translate storage outcomes where the resource is known: a taken rule or source ID is a `409` naming the resource, and `Errors` has no storage-specific handler. Text that PostgreSQL cannot store (U+0000 in a name, description or definition) is a `422` raised by `StoredText` before any write. Request bodies are read strictly (`spring.jackson.deserialization` in `application.yaml`: unknown properties, a second document after the body and a fraction where an integer belongs fail), and `Errors.malformed` names an unknown field's path in its `400` (`definition.inputs[0].source.pointr`). Stored JSON is read leniently (`JsonCodec.decode`), so a field a later model drops never makes a published version unreadable. Draft and source saves encode with `JsonCodec.encodeEditable`, which refuses (`422`) JSON that responses would write larger than `Limits.MAX_EDITABLE_JSON_BYTES` (960 KiB), because stored numbers are written out in plain decimals and the editor sends back what it read in its next save; publishing copies a saved draft and uses `encode`.

`RuleExecutionService` creates one `MemoizingRuleResolver`, one source configuration session, one execution-plan session and one `Parameters` instance per execution. The resolver is keyed by rule ID and version; the source session shares pinned configuration between static validation and live provider reads. The configurations themselves are the frozen copies of `SourceVersions`, one process-wide cache (256 entries, 16 MiB of estimated retained heap: every value weighs its digits, characters and entries, parameter defaults included) that static checks read too: a version is immutable and a source is never deleted. It keeps only the frozen `SourceDefinition`; a source's name belongs to the source, not to a version, and may change. These request caches, input scopes and read budgets never become singleton state. Executions and previews evaluate on `EvaluationThreads`, cached daemon threads with 4 MiB stacks: the deepest evaluation the limits allow (17 nested rules, each inside expressions nested 48 levels deep) needs about 1.5 MiB before the JIT compiles the evaluator, more than the 1 MiB of a request thread on Linux x64. The engine separately owns a bounded cache of immutable compiled published plans (128 entries, 8 MiB estimated weight units, not measured heap bytes). A published execution passes its pinned definition as a `Supplier`, so a cached plan runs without reading and decoding that version again; an uncached version is read first, keeping the `404` for a missing version. Deleting a rule is the one end of a pin's immutability: after the deletion commits, `RuleService.delete` calls `Engine.forget`, which drops the rule's cached plans, and sessions that began before it no longer cache plans, so an ID used again never runs a deleted rule's plan. That eviction is local to the API process; ARC ships as one API process per database (compose binds one fixed port), and a second process would keep serving a deleted pin from its own cache until eviction. Preview roots are request-local. Static diagnostics inspect source definitions but never fetch external values. `ExecutionResponse` wraps `Engine.Result` with `@JsonUnwrapped`, so the execution JSON keeps its flat field order; `PayloadSnapshotTest` pins it. Sample rules are seeded once per workspace: startup claims the `rule-samples` row of `workspace_seeds` (`RuleRepository.claimSampleSeeding`, an `ON CONFLICT DO NOTHING` insert inside the seeding transaction) and never loads stored rules, so a workspace whose rules were all deleted is not seeded again. The samples are written behind a savepoint: the API accepts requests before the seed runs, so a sample ID may be taken, and then only the samples roll back, with a warning; the claim stays and the API starts.

Within `engine.execution`, the stateless `Engine` facade creates a `GraphExecution` for each call. That session owns nested rule dispatch, active-rule guards and the shared trace. Each rule invocation keeps its compiled graph, depth, executed scopes, chosen branches and reached Outputs in a private `RuleRun`; `Parameters` keeps one call's declarations and resolved values in a private `Resolution`. `ExecutionScope` owns values, their producing nodes and, for each write, the write its producer replaced on the path that ran. A join keeps a value only when it superseded every other candidate there, so a write linked to an earlier one only through a skipped branch conflicts instead of silently winning. Scopes are immutable: a node that stores no result shares its single parent's scope, storing a result copies the scope once, and expressions read a view without another copy. `Parameters` owns recursive source argument resolution in declaration order, overrides, fallbacks and the shared read budget, and checks the deadline before and after every read. Keep these policies together when extending execution; a node-kind hierarchy would obscure the related branch and join invariants.

`engine.expression.Expressions.compile/evaluate` and `Compiled.variables/evaluate` are the expression entry points. `ExpressionParser` owns tokenization, precedence and lexical dependency analysis; it compiles without evaluating data. `ExpressionRuntime` owns operators, lazy functions and scoped collection execution. Published Formula expressions use `@id:version(...)`; the parser exposes call metadata separately from free variables, and `Compiled.variables()` lists free variables in source order, so dependency resolution never depends on hashing. A narrow Formula callback carries reached calls into the existing graph session. `RuleResolver.resolveFormula` verifies the pinned entry is a Formula; ordinary reference resolution does not imply that capability. Each evaluation gets an explicit context and operation budget; exhausting that budget is a `LIMIT` error that error functions cannot hide. Collection items bind their local identifiers in front of the evaluation's scope without copying it, so an item costs the same for 2 or 150 upstream variables, and inner locals shadow outer names. Child collection scopes share the operation budget, while separate or reentrant evaluations do not. Compiled code is immutable and hides its raw evaluation nodes, so callers cannot bypass the evaluation boundary. ARC keeps no thread-local execution state or independent global expression cache; POI's thread-local locale and time zone are set only for the duration of one POI call. A compiled graph retains its validated expressions for reuse; each evaluation still creates its own scope and operation budget, while sharing the request deadline.

String literal decoding uses a private Jackson `JsonFactory` configured for ARC's existing single quotes, unknown escapes and raw control characters. It does not change the application's HTTP, source or stored-JSON parser settings. Quoted tokens use possessive patterns, so long literals never recurse once per character. `ExpressionCompatibilityTest` covers the language contracts needed by any future parser/library replacement, including decimal literals, strict types, case-sensitive names, lazy failures, missing/null values and repeated/concurrent execution. See [the library assessment](reviews/2026-09-22-library-options.md) before substituting another engine.

`Functions` is the evaluator-facing facade. `FunctionCatalog` assembles immutable capabilities and checks arity. `BuiltinFunctionCatalog` pairs ARC-owned help with argument bounds; `ExcelFunctionHelp` supplies typed documentation overrides, and `ExcelFunctionCategories` groups the remaining POI entries. `ExcelFunctionAdapter` owns POI value conversion and invocation. It pins POI's locale (`Locale.US`) and time zone (UTC) for each call and clears them afterwards, rejects arrays in POI value parameters (from POI's `FunctionMetadata`), defines empty-range results, and returns POI numbers without a negative scale. `ExcelText` formats `$TEXT` without POI's static formatter caches and refuses format codes longer than Excel's 255 characters. `ExcelCallShapes` adapts the calls POI answers differently from Excel before it runs (ROMAN's form, INDEX with an area, IPMT and PPMT with a future value and type, CODE's number, COUNTA's minimum of one argument), and `ExcelDateText` refuses year-less date text in every argument POI reads as a date. `ExcelMatchingWork` bounds the work of POI's wildcard and number-parsing patterns before POI runs, because POI's regexes cannot be interrupted; a new POI function that matches `*`/`?` patterns or parses range text as numbers must be added there, and its catalog-wide test flags one that was not. ARC decimal operations retain their existing semantics; POI calculations retain Excel floating-point semantics. Ordinary functions are entries in the `Functions` dispatch table, and lazy functions are entries in the `ExpressionRuntime` table (`IF`, `IFERROR`, `COALESCE`, `AND`, `OR`, `SWITCH`, `CHOOSE` and the `IS…` error functions). Collection functions are the `CollectionFunction` constants (the parser reads their bindings, and `ExpressionRuntime` runs each constant's per-item step and final value as exhaustive switch expressions) and decimal aggregates the `DecimalAggregate` constants (each computes its own value); `BuiltinFunctionCatalog` documents both from the enums, so a listed name without code cannot compile, and `FunctionCatalogTest` fails when an ARC catalog entry has no ARC implementation. Change the parser only when a function introduces binding syntax, such as the item/accumulator identifiers in `REDUCE`. The catalog fixtures preserve API order, help, snippets and arity; update them explicitly for intentional capability changes rather than regenerating them to accept a refactor.

`engine.validation.Validator` coordinates `GraphValidation` for executable checks and `GraphDiagnostics` for editor diagnostics. Both reuse `DefinitionShape` for draft structure and limits and `NodeValidation` for node semantics. `NodeValidation.expressions` and `NodeValidation.sourceMappings` are the only enumerations of owned expressions. They label every expression (`Route / Case Premium`, `rate source / region`), and `NodeValidation.check` applies that label to its problems. `ExpressionPositions` owns the position wording (`Selector`, `Case Premium`, `Field cost`, a binding's parameter, `rate source / region`); runtime errors add the position alone through `ArcException.withContext`, which prefixes only recoverable errors, so a limit or the deadline keeps its message wherever it is raised. Executable validation stops at the first problem. Diagnostics run the same steps once and collect the problems: every expression compiles once through an `ExpressionCache`, and the scope plan is built once. A cyclic graph without a scope plan still gets every node check but variable availability, and diagnostics report every connection and reachability problem, while validation stops at the first. `DefinitionShape` reports its first violation as a `ShapeViolation` naming the offending element; validation places it on that element's node (a connection belongs to the node it leaves), and ARC Script places it at the element's statement. Whole-graph and input problems appear on the Input node (`Validator.onInputNode`, backed by the `Problems` collector); a draft without an Input keeps them unlocated. `InputValidation` owns input declarations and source-binding shape, using the shared identifier/type policies. `DefinitionShape` also checks supplied result-variable and Output field names, so saving an unfinished draft cannot bypass identifier syntax. It lets a Reference choose its rule before its version, but not the reverse. It rejects a property that the node's kind does not use (`NodeKind.properties()`) at that node, in new drafts and stored versions alike, so the checks after it read only a kind's own properties. Add a node's expression fields to `NodeValidation.expressions` so incomplete or cyclic graphs get the same syntax coverage as executable graphs. Diagnostic collection must retain partial graph locations and must not fetch source values. `Validator.diagnose` also returns the rules the graph calls, minus the pins its checks rejected; `RuleDefinitionService` passes them to `SourceBindingValidator`, so each fault is reported once, by its owner.

`engine.graph.GraphPlan` exposes order, incoming/outgoing edges and guaranteed variables through read-only accessors. `GraphTopology` owns graph indexing, stable topological order and locating a cycle error on the nodes of one cycle; `BranchScopes` owns conditional variable availability, deriving its first-match gates from each node's handles and numbering its tests in a topological order derived from the connections (the reverse postorder of a depth-first walk from the Input node), never from node IDs, so renaming nodes cannot change whether the analysis fits its caps while execution and traces keep `GraphTopology`'s ID tie-break. No single numbering suits every graph, so the analysis tries three in turn (a handle's targets with the most decisions below them first, the fewest first, then the connections as drawn, the only order before 2026-10-01) and reports a graph too complex only when none fits; the scopes do not depend on which one fits. `BooleanConditions` owns the bounded Boolean decision diagram operations. Keep the scope algorithm cohesive: it reasons about mutually exclusive branches and simultaneous writes, rather than enumerating every execution path.

`Validator.compile` produces a `CompiledGraph` containing the checked topology and parsed expressions. `ExecutionPlans` reuses that object between application preparation and graph execution, within repeated reference calls and across immutable published pins. The cache stores `Definition.detached()` copies (unmodifiable collections, frozen input defaults) and uses entry/weight bounds. A plan's weight counts fixed node and connection costs, its compiled expression text, its serialized JSON size and its scope plan (every variable in every node's scope), so adding a field needs no weight change. The cache is discarded on process restart; it never stores inputs, results, source values or mutable drafts. Embedded `Engine.execute` callers retain request-only behavior because their supplied definitions need not represent immutable database versions. The source-contract check of a published root runs once per cached plan (`Engine.Session.verifyOnce`): the version, the pins it reaches and their source versions are immutable while it lives (a rule another rule calls cannot be deleted), and `forget` drops the verdict with the plan. A preview is checked on every request, with the source session the runtime reads use. Validate, diagnostics and publish prepare each reached pin with `Engine.prepareForCheck`: the plan an execution cached, else a plan compiled for this check only. A check stores no plan, because it may read versions its transaction has not committed (the sample seed publishes in one transaction and rolls back when an ID is taken), and it runs without the execution deadline. Validate and diagnostics read published definitions through `Engine.cachedFirst(rules)`, so a pin an execution cached is not read and decoded from storage again; Formula calls still ask storage, which checks the rule's kind, and publish reads storage inside its transaction. Referenced graph plans are prepared when reached, preserving branch/error behavior.

`engine.script.ArcScript` is the studio facade. `ArcScriptScanner` tracks statement boundaries, quoting, comments and source locations (a `//` outside quotes starts a comment anywhere, inside a statement or header too, and becomes a note); `ArcScriptParser` owns document declarations and input schemas; each `ArcScriptNodeParser` owns one node's declarations, expressions, pins and outgoing edges. `ArcScriptSyntax` shares lexical forms and strict JSON literal decoding (unknown fields, trailing text and fractional versions are refused whatever the application's mapper allows), and `ArcScriptRenderer` produces canonical text. The renderer writes only what a draft holds, and only what reads back as written: an expression that would not scan as one value (a `;`, `}` or `//` outside quotes and brackets, or an unclosed quote or bracket; `ArcScriptScanner.scansAsOneValue`) is refused with a `422` at its node rather than rendered into other statements. An unset value omits its statement, and an empty value is written empty: `return;`, `select;`, `let total =;`, `let total;` (no expression yet), `let = amount;` (no result name yet) or `use "rule-id";` (no version yet). The parser accepts exactly these forms, and empty result and Output names read back as unset. `ScriptLocations` records the statement that declared each node, case, field, connection, input and comment, so draft-shape problems found while building point at that statement. Connections written without `edge "id"` get `source-handle-target` IDs; when a node ID contains a hyphen or the result exceeds the edge-ID limit, the ID keeps a bounded prefix and adds a digest after `~`, so generated IDs stay valid and unique. Single-node replacement belongs to the facade because it combines a parsed fragment with its containing graph. A fragment may replace only its node and outgoing edges (plus parameters for Input); incoming edges, unrelated nodes and graph notes remain owned by the containing graph. A build compiles every expression it reads, source mappings included, and reports a problem at the statement that holds it. Grammar changes need both parser and renderer changes, with canonical-text and round-trip tests. The embedded parser bounds source at 1,048,576 characters; HTTP independently limits the encoded JSON request to 1 MiB bytes.

### Adding a data source

1. Implement `SourceAdapter` in a provider package as a Spring component with a unique `kind()`, configuration validation, and the single `fetch(sourceId, definition, inputs, deadline)`. `SourceAdapters` discovers it through constructor injection and rejects duplicate kinds on startup. No dispatch branch is needed in either source service. The deadline belongs to the execution, and a source Test uses the default 30,000 ms one. A provider that blocks on IO must stop when the deadline expires; the caller checks it before and after the call.
2. Preserve strict typed input/default handling in `SourceExecutionService`; return the provider's JSON-compatible value. Field extraction stays in `JsonPointerExtractor`, which walks the provider's parsed maps and lists, so return JSON-compatible `Map`/`List`/scalar values. Missing/fallback policy stays in `engine.execution.Parameters`.
3. If the provider needs new configuration, extend the portable `SourceDefinition`, frontend `SourceConfig`, source form, API specification, and ARC Script round-trip handling where applicable. Registering a strategy alone does not create its UI or storage contract. Unsupported-kind errors are generated from the registered kinds. `SourceValidator` checks the kind-independent contract: parameters, and that secret header names and aliases are present. A provider declares the optional fields it reads (`SourceAdapter.fields()`, with `noun()` for its messages), and `SourceValidator` refuses any other field that is set before the provider's own `validate` runs ("Lookup tables do not use secret headers", "HTTP sources do not use lookup entries"); `timeoutMs` is outside that rule.
4. Test the adapter independently and add an API workflow for source creation, pinned versions, missing values and failures. For HTTP-based implementations, reuse the bounded transport and host/secret policy rather than creating an unrestricted HTTP client.

`SourceService` owns versioned configuration commands and their transactions. `SourceExecutionService` owns test/read dispatch. Each execution opens one `Session`, which implements the engine's narrow `SourceReader` port (one `read(binding, inputs, deadline)`) and snapshots the frozen pinned configurations of `SourceVersions` (`SourceDefinition.detached()` copies of what is stored). An omitted test version uses `SourceRepository.latest` to read the persisted current pointer and definition once; an explicit version or rule binding remains pinned. Neither path loads the full version history. `JdbcSourceRepository` shares one select (`VERSION_ROWS`) and one typed row mapper across those reads, and every version read of an unknown source, including the legacy full history, returns `404`.

`SourceServiceTest` and `SourceExecutionServiceTest` demonstrate an additional provider through configuration validation and typed reads. Use that pattern for new providers. `SourceConfigurationConsistencyTest` checks that a configuration either fails when saved or behaves the same in Test and execution. Use repository mocks for command ordering and rejected writes; real PostgreSQL smoke tests cover actual revision locks, transactions, and latest/pinned selection.

Within `source.http`, `HttpDestinationPolicy` owns configured URL/host/secret-header policy and implements HttpClient5's `DnsResolver`, checking IP addresses when the connection resolves. Configuration validation itself does not perform DNS or HTTP requests. `BlockedAddresses` classifies each resolved address by its raw bytes against explicit IANA ranges. IPv6 forms that carry an IPv4 address (IPv4-mapped, IPv4-compatible, NAT64 `64:ff9b::/96`, 6to4) are judged by that address; other IPv6 destinations must be global unicast outside the Teredo, benchmarking and documentation blocks. Keep ranges explicit, test both sides of their boundaries, and build IPv6 test answers as real `Inet6Address` values; the JDK parses `::ffff:a.b.c.d` literals into `Inet4Address`. An allowed hostname does not grant a private-address exception. `HttpSource` owns request construction (the configured query text is kept byte for byte and parameters are appended percent-encoded, numbers as `$TO_STRING` text), a lifecycle-managed connection pool (100 total/20 per route), per-call cancellation bounded by the shared execution deadline, bounded response parsing (a rejected status or oversized body cancels the request, discarding the connection instead of downloading the rest) and transport error translation; changing destination policy should not require rewriting that transport. `HttpSourceAdapter` connects those responsibilities to the registry. The local table provider remains in `source.lookup`.

### Adding a function or node kind

For a function, update catalog metadata and its execution implementation, then test arity, types, edge cases, and a studio build/execution round trip. A reference-only entry must never advertise itself as executable. Monaco help and function chips use `/api/functions`, so they should not duplicate a handwritten function catalog. All editors read it through `useFunctionCatalog`, which shares one request per page load and forgets a failed read so that the next editor retries.

Public function names and signatures include `$`; internal dispatch names remain unprefixed. Catalog snippets escape each literal dollar as `\$` for Monaco while preserving `${n:...}` argument placeholders. Include nested calls in that rule. Completion ranges consume an already typed `$` exactly once, and function hover must not mistake a same-named input for a call. The parser rejects unprefixed calls in every entry point, including old stored expressions. This is an intentional language compatibility change; fixing an old rule requires editing its draft and publishing a new version, never rewriting published JSON in place. Parameter declarations retain `Identifiers` syntax, excluding whitespace and `$` in rule and source inputs.

`domain/expressionSymbols.ts` classifies visible names for model-scoped Monaco semantic colors. It is presentation logic, not a second expression evaluator. Preserve parameter/result metadata from `VariableOption`, skip literals/comments, classify only a dotted path's root, and respect collection-local shadowing. Inline editors use the authoritative available scope; script editors color declarations without claiming execution validity. Track node kinds when classifying Script `as` clauses: Output aliases are field names and must not replace a same-named input’s symbol role. Providers return no tokens for unrelated models and are disposed with the editor. Published Formula metadata is loaded on explicit `@` completion, hover or picker use, with bounded pages. `features/studio/formulaMetadata.ts` keeps one page-wide cache of input metadata keyed by the `id:version` pin (64 entries, least recently used first); only completed reads are kept, and a newer catalog summary refreshes a cached display name. A pin is immutable only while its rule lives, so each entry remembers the rule's creation time and serves only that incarnation: a search or insertion compares the catalog summary's `createdAt`, hover reads the rule once, and a re-created ID downloads its version again and re-checks the Formula kind; `forget(id)` drops a rule deleted in this page. `@` completion searches once the text has not changed for 150 ms: Monaco keeps a completion request open while the user types ordinary characters, so the provider waits for the pause and searches the prefix typed by then. Its results are marked incomplete, so a longer prefix searches again. Async insertion rechecks the model, its version, selection and read-only state before writing. Formula completion arguments use the latest authoritative scope at acceptance, because Monaco can retain an older visible option while refreshing suggestions. Inspector sections share default-expanded MUI accordions with independent help/actions beside each heading. `ExpressionField` owns the **Available variables** action above each inline editor; `AvailableVariables` keeps its preview and nonmodal pinned panel above the trigger, outside the editable layout. The pinned panel permits editor interaction and closes only through its X; dialog-contained portals preserve the enclosing focus boundary. Non-expression binding modes do not mount this action.

A node kind changes the graph contract, not just a switch statement. On the backend, add the constant to `dev.arc.model.NodeKind`, whose name is the JSON `type`, and answer each of its facts: `storesResult`, `handles`, `choosesOneExit` and `properties`. The facts and the per-kind behavior (`GraphExecution.evaluate`, `NodeValidation.expressions`, `ArcScriptRenderer.declarations`, `ArcScriptNodeParser.declarationKeywords`) are exhaustive switch expressions without a `default` branch, so the backend does not compile until each owner handles the new kind; keep it that way. Then review draft shape, frontend types, the node-kind descriptor in `domain/nodeKinds.ts` (the compiler then requires the kind's icon in `components/Icons` and its form in the inspector registry), stylesheet tokens for the kind's class key, and documentation together. Add path/scope tests and a code/graph round trip. Node kinds deliberately remain explicit in the engine; a plugin hierarchy would hide the graph invariants without helping these related execution behaviors.

`NodeKind` states which kinds store a result, which handles each connects and which optional properties its nodes may set (`properties()` is the one table of a kind's expressions, result variable, pin and Output name, and `storesResult` is `uses(Property.OUTPUT)`); `Handles` names the handles (`Handles.forCase(id)` builds `case:<id>`). `Definition.inputNode()` is the one Input lookup: the first `INPUT` in document order. Validation requires exactly one Input. `Definition.Node` has one canonical constructor and `Definition.detached()` copies every field through it, so a new field fails to compile until the copy threads it. Tests build nodes with `support/GraphFixtures` (`nodeOf(id, type, label)…build()`, `inputNode`, `outputNode`, `copyOf(node)`), never with positional `Node` constructors. `OUTPUT.outputName` names a returned field, not a scoped variable; retain it through detached compiled-plan copies and graph/node Script round trips. An empty result or Output name means that no name is chosen yet: `Node.resultName()` and `Node.outputFieldName()` read both as null, and scope analysis, draft shape, the renderer and execution use them rather than testing for `""` themselves. A single reached Output keeps its optional wrapper. Multiple reached Outputs aggregate raw values using Output name, then a valid bare variable expression, then node ID. Use the shared identifier policy, keep the raw value separate from its single-Output wrapper, and reject duplicate reached keys with both node locations; never flatten arbitrary object values or reject aliases solely because mutually exclusive nodes share them. `OutputValueFields` shares the value/name controls between ordinary Output forms and the exclusive Switch default shortcut. On the frontend, `domain/nodeKinds.ts` states each kind's exits and whether it accepts incoming connections; `domain/nodePorts.ts` turns them into the stable handles, positions and card widths that graph mutations, canvas rendering, previews and layout share. Switch case order controls first-match priority; its case IDs own the connections. `DataFunctions` owns object construction and explicit scalar conversion, while lazy `COALESCE` stays with the expression evaluator.

Import the relevant resource client from `api/rules`, `api/sources` or `api/studio`, and transport errors from `api/errors`. The unused aggregate facade has been removed. Pure domain functions and the document reducer must not import React, MUI, React Flow or network clients. They can be tested without mounting the editor or starting a server. HTTP clients may import `domain/json` but no other domain module. [The architecture check](#architecture-check) lists every module it keeps pure and guards shared controls from importing application/feature orchestration. Three unit scans in `tests/unit/code-conventions.spec.ts` add conventions the type checker cannot: no nested ternaries, every exported value used by another module or a test, and browser specs that reach the rule API and unique IDs only through `tests/helpers/api`.

JSON numbers keep their decimal value across the browser. `api/http` parses response bodies with `parseJson` and writes request bodies with `stringifyJson` (`domain/json`). When a double would change a number's decimal value (integers above 2^53, more than about 17 significant digits, or values outside the double range such as `1e400`), the number arrives as a `DecimalNumber`, and the same token is written back. A number stays a plain double only when writing that double back gives the server the same value with the same decimal places (`decimalKey`); `2.50`, `1.0` and `0.070` therefore arrive as `DecimalNumber` and keep their scale, and only exponent spelling may change (`1E2` becomes `100`, `-0` becomes `0`). Code that inspects JSON values must handle `DecimalNumber` (use `isJsonObject`/`isDecimalNumber`, not `typeof value === "object"`). Node positions are UI doubles that the server writes as `400.0`: `withNodePositions`, which every draft passes on its way into the editor (open, version load, build, node fragment, adopted save response), turns such coordinates into numbers, because position arithmetic on a `DecimalNumber` concatenates text. Editable JSON buffers and displays use `parseJson`/`parseJsonObject`/`stringifyJson` rather than `JSON.parse`/`JSON.stringify`: plain `JSON.stringify` keeps the digits only where the engine provides `JSON.rawJSON`, and writes a quoted string elsewhere. `doubleKeepsDecimal` is the shared test used by numeric defaults and the codec, and `decimalKey` the shared value-and-places key. Parsed objects follow JavaScript property order, as with `JSON.parse` (integer-like keys first, ascending, then the others as written), while stored order is JSONB's; displays therefore show the browser's key order, and `tests/unit/json.spec.ts` pins it so a codec change is deliberate. A successful response must carry a readable JSON document: an empty, truncated or non-JSON 2xx body rejects with an `ApiError` that keeps the status, and 204/205 resolve `undefined`. Error bodies stay optional JSON. `createHttpClient(...).url(path)` returns the URL the client requests, so endpoint modules can build links (for example `ruleApi.executeUrl(id, origin)`) without repeating the `/api` base or path encoding.

Place a component beside the feature that owns its behavior. `components/` is for controls usable independently of a particular feature; multiple callers alone do not make a domain editor generic. Shared rule-reference types belong to `features/editor/types`, so execution/error views do not import a dialog for their contract. Monaco, ELK and the rule editor route (React Flow and its stylesheet) remain behind lazy feature boundaries. `vite.config.ts` code-splitting groups give React its own chunk, because a group also takes its modules' dependencies: React in the `flow` chunk would put React Flow on every route.

Lazy features keep `React.lazy(() => import(...))` and render inside `<LazyBoundary label="…" fallback={…}>` instead of a bare `<Suspense>`. A failed chunk or a render error in the subtree shows a local error, and the editor, its siblings and the unsaved draft stay mounted. A failed chunk fetch stays failed until the page reloads: the browser keeps the failure in its module map (in Chromium, a repeated `import()` rejects without making a request), and `React.lazy` keeps the rejection. Try again therefore clears the error and remounts the children, which recovers render errors only; the message tells the user to save and reload. Tests should assert that the application stays mounted and the draft survives a chunk failure, not that Try again loads the chunk. Lazy dialogs pass `onDismiss`, because the failure message replaces the dialog and its close button. `main.tsx` renders the application inside a root `RecoverableBoundary`, and `App` wraps the routed view in another keyed by the route, so a render error leaves the sidebar usable and navigating away recovers. `createRoot` logs caught and uncaught errors. `watchChunkLoadFailures` records `vite:preloadError` before the first render; the workspace then asks the user to save and reload. The event is not cancelled, so the failing lazy boundary still shows its local error.

Use file length as a review signal, not a quota. A component around 200–300 lines should prompt a check for mixed responsibilities; retain a longer cohesive coordinator or algorithm when splitting it would merely forward props or fragment an invariant. Extract independently changeable regions, name their inputs/actions, and remove migrated entry points. Avoid duplicating state to make individual files shorter.

Rule and source IDs follow the API slug policy in `domain/resourceIds.ts` (`isResourceId`, the server's `Identifiers.isResourceId`), distinct from expression identifiers: lowercase letters, digits and hyphens, starting with a letter, at most 80 characters. `ResourceIdField` refuses forbidden typing and pasted whitespace for both the create-rule dialog and new sources; each command checks the complete value again before submitting. A generated Rule ID follows the name until the user types their own ID; clearing the ID resumes suggestions. Generated IDs add a letter prefix for names starting with digits so the producer obeys the server contract.

`useWorkspaceNavigation` owns the route, the rule's dirty flag and the only `beforeunload` listener. `navigate(path)` asks before changing the hash. Browser traversals are confirmed after the fact: each history entry records its position in `history.state`, and a cancelled change is undone with `history.go(delta)`, never by rewriting an entry. Route parsing returns a discriminated `WorkspaceRoute`; add a page to its union and the exhaustive switches in `App`, `Sidebar` and `WorkspaceHeader` together. Work that a route change would discard registers `useNavigationGuard(message)` while it is at risk, for example the source editor's unsaved edits or pending save. A guard applies to every route change by default; `useNavigationGuard(message, applies)` narrows it with a stable, module-level scope function. `activeNavigationGuards(change?)` returns the messages that a route change, or a page unload when `change` is omitted, must confirm; the workspace asks once with all of them. The pure `routing.ts` defines `leavesRuleDocument({from, to})`, the one rule for "this change closes the rule editor"; the rule's unsaved-draft warning and the editor's pending save/publish guard both use it, so a graph/code switch of the same rule asks only for work it would discard.

Graph and code edits share one document reducer. Building code updates the graph atomically; failed code builds preserve the buffer and prior graph. Saving advances the saved baseline. Node measurements never enter the graph document. Arrange results carry the draft they started from, so a late layout cannot replace a newer edit. Drafts entering the editor (open, version load, build, adopted save response) get origin positions for nodes that have none.

Graph element IDs come from `domain/ids`: `newId()` for edges and `shortId(prefix)` for nodes, cases and generated Outputs. They use `crypto.getRandomValues`, because `crypto.randomUUID` does not exist on plain-HTTP origins other than localhost. Choose IDs in the event handler and pass them into the document updater: React may run an updater more than once, so updaters must stay deterministic. `createGraphNode(definition, type, id, position)` names new results with `uniqueName("result_", …)` over all input parameters and node results. `canRemoveGraphNode` and the descriptor's `storesResult` are the shared node-deletion and result-kind rules. Values keyed by user-chosen names (node, edge and parameter IDs) use `Map`/`Set` or `ownValue`, and user-named keys are written through `withBinding`: IDs such as `constructor` and `__proto__` are legal. Error locations are classified by `isCurrentGraphLocation`/`isPreviewRoot` in `domain/graph`.

Code builds belong to one mounted editor session. Closing that session aborts pending builds; neither a successful switch nor its failure fallback may navigate after closure. `useRuleDocument` owns this lifetime and passes the session signal to builds, view switches and every save, validate and publish request, checking it after each await so that no further write starts after the session closes. While a save or publish is pending it registers a navigation guard scoped with `leavesRuleDocument`, because an aborted request may still have reached the server. Opening the same rule again creates a fresh session. The header's view switch is a command that checks first and navigates after a successful build. The sidebar and browser history change the route before the editor sees it, so those switches cannot be refused up front; the editor applies the same rules on arrival: code with an invalid default returns to the graph, and unbuilt code builds before the graph shows (a failed build returns to the code). A refused arrival is corrected with `redirect`, which undoes a just-pushed entry with `history.go(-1)` and rewrites an entry reached by Back or Forward, never adding an entry; the arrival rules apply once a running command releases the lock, and a buffer whose arrival build failed returns to the code without building again. `shownView` keeps the rendered view consistent in between, and the header toggle names the view on screen (`viewToggleLabel`). Deleting the rule is the `delete` command in rule settings. It sends the revision the editor read (`ruleApi.delete(id, revision)`), so a rule published or replaced elsewhere answers 409 in the dialog, which stays open while the deletion is pending and lists every caller of a refused deletion (`ApiError.issues`, `errorDetails`). A deletion cannot be recalled once sent, so it carries no session signal: whatever happens to the editor, the outcome reaches the workspace as "Rule X deleted" or "Rule X was not deleted: …", `onDeleted` runs, and `App` forgets the rule's saved copy, library page, Code studio target and Formula metadata (`formulaMetadata.forget`). Only a still-open editor then reports itself clean and leaves for the library; `useWorkspaceNavigation`'s `setDirty` updates what `navigate` reads at once, so leaving does not ask about the deleted draft. A `404` for a rule route shows "Rule not found" with "Back to library" (`useAsyncResource` keeps the failure's `status`), never a retry. Unused node properties (`unusedProperties` in `domain/nodeKinds`) appear in the inspector, whose **Remove** clears them through an ordinary node patch.

Arrange ends its command when the layout is applied and asks the canvas to fit through a fit request in canvas state; the mounted canvas performs it on the next frame and nobody awaits it. Do not await a cancelable React Flow transition while holding the document's command lock: user input or unmounting the canvas can leave the returned promise unsettled. Other optional viewport animations must not control whether draft commands become available again.

Save acknowledgements also carry the submitted rule. The reducer advances the server revision and saved baseline while preserving edits made after submission; a stale code build must not replace a newer buffer. The response differs from the submitted draft only in key order and explicit nulls, so the reducer keeps the local draft object when `sameDefinition` holds; derived identities (diagnostics, variables, preview inputs, input rows) therefore survive a save. Disabled controls communicate pending commands, but reducer checks enforce the draft contract independently of those controls. Controls read `capabilities` from `useRuleDocument`. Edits go through `edit`, `editMetadata` and `editSource`, which return whether the document accepted them: callers move the selection or close a dialog only after an accepted edit. The reducer's `dispatch` is not exported.

Read-only guards belong at command entry points as well as UI controls: a hidden Save button does not disable a Monaco keyboard action. Both use the same rules (`editorCapabilities`): the UI derives them from the rendered state, and entry points derive them from the command that is running at that moment. The code buffer is the one exception: it is refused only for published versions, because Monaco has already applied a keystroke that races a starting command, and that command's build then reports the newer buffer. The buffer belongs to the document: `CodeStudio` mounts Monaco with `defaultValue` and follows the document's source through `adoptSource` (one undoable edit of the changed span, never `editor.setValue`), so a command's canonical rewrite keeps the caret and the undo history. Published-version loading has explicit loading/ready/failed states. A failed version fetch must not reveal the initial current draft under a historical-version label or send its definition for diagnostics, testing or export. Callers mount the document controller with a key containing rule ID and requested version; in `App` that key sits on the editor session's `LazyBoundary`, so a failed editor chunk or render error resets with the session. Retry stays within that version's session. A new rule selection must finish its detail read before a cached save acknowledgement can initialize the editor. Revision changes from saving do not remount an active document. The version history's page key includes the latest published version, so a publish refreshes an open list. The selected node is derived from the current draft (`nodeSelection.ts`).

Preview and published execution share a narrow request hook. Its key includes the graph/version and input buffer; changing either, rerunning, or unmounting invalidates the previous request. Only a current result may update the graph's trace or error locations. The editor's preview session lives in `usePreviewExecution`, above the graph/code switch; `TestPanel` presents it. Its key uses `semanticGraphKey`, so moving cards keeps the result and its trace. The Test panel and the playground share `useInputBuffer`: an untouched input buffer is derived from the current sample and follows input changes, and an edited buffer is kept for its target (the editor session or a rule version). Closing the panel discards the result and a pending run but keeps inputs and options; unbuilt code disables Run with a build-first state. Example inputs (`sampleInputs`, and `sampleInputsJson` for the editable buffer), JSON-object parsing (`parseExecutionInputs` for commands, `tryParseExecutionInputs` for previews) and cURL formatting live in `domain/executionInputs.ts`, so the API page does not import a test-panel component for data helpers. `sampleValue` is the one example-value policy for rule inputs and source parameters. `curlExample(endpoint, inputs, version, options)` receives its URL from `ruleApi.executeUrl` and prints `{}` whenever the buffer is not a JSON object. The playground pages its published-rule catalog and version history with `usePagedResource`, and its rule search waits `searchDelayMs`; while a typed search has not applied yet, the Rule selector counts as loading. A release that only the history reveals is remembered outside the history key, so learning it does not read the same page again; the selected rule's summary is refreshed when a catalog page shows a newer release or another incarnation of the ID (`publishedSelection.ts`, using `sameRule`), and releases learned from the parent library page or the history count only for the selected incarnation. A version read or execution that answers 404 abandons the pin, clears the selection and reloads the catalog once; an abandoned pin keeps its error afterwards, so a stale library row cannot make the playground reselect it without end. When the buffer is not a JSON object, the playground's cURL example sends empty inputs and the page shows a warning.

Each source selection receives a session identity. Save responses update the source list and carry their source, selection and request identities. They cannot select another source or replace newer edits. Reopening the same source during its save can adopt the completed server revision while preserving any subsequent changes; only a stored copy does so, and a new draft that took a pending create's ID keeps its state, is pending only through its own request and receives the server's 409 from its own Create. Test responses additionally belong to the selected version and input buffer. Historical source metadata completes separately from version selection: only an untouched test buffer receives the loaded version’s sample. Save acknowledgements also preserve edited test inputs independently of configuration dirty state, including when the source was reopened during the save. Source saves parse and submit only fields for the active provider, preserving inactive raw buffers during provider switches. Source reducers and buffer helpers stay free of React and network calls, allowing these race conditions to be tested as state transitions. Source buffers use the lossless codec: an unchanged lookup table saves as a new version with every digit. Saves require JSON objects for lookup entries and secret-header aliases (text values), and `parseSourceTestInputs` reads the test buffer. Source parameters are scalar, so their sample values never need array or object placeholders. The loaded configuration of a historical version is document state (`viewedConfiguration`, shown through `displayedConfiguration`). `canRunSourceTest` is the single test-eligibility rule for command and button, and `sourceSaveProblem` blocks saving invalid new IDs, HTTP timeouts and HTTP URLs the transport could not send as written (`httpUrlProblem`: raw non-ASCII characters, ports outside 1–65535). The HTTP timeout is a raw text buffer (whole milliseconds from 100 to 10,000). Saved sources replace older catalog rows and appear first on page 1 only until a catalog read issued after the save completes (`sourceCatalog.ts`); the server decides search membership and order.

Async reads use a key describing the requested resource, an `AbortSignal`, and cleanup on selection changes/unmount. `semanticGraphKey` excludes positions: dragging a card changes the draft but does not refetch variables or diagnostics or discard a preview result. A different expression or connection does. If a new consumer adds a query parameter, include it in the key; changing a loader closure alone does not refetch. Mutation commands remain explicit and serialize through the document controller. Canvas element builders return the previous React Flow node or edge object when nothing it shows changed, and the routing context is keyed by card geometry, so a text edit re-renders one card and re-routes no edge. `GraphNode` is memoized and every React Flow handler is stable (`useCallback`, with the selection setters read through a ref), so that claim holds: typing a name on a 100-node rule renders about one card per keystroke. While a card is dragged, the routing context also carries the moved cards' bounds before and after (`moved`), and `routeWithCache` routes an edge again only when an endpoint moved, the edge is attached to a moved card, or a moved card's old or new body meets the edge's route box; the drag's end (`dragging: false`) routes every edge once more, because the obstacle grid depends on every card. Arrange runs ELK in a Web Worker (`graphLayoutWorker.ts`, created on the first Arrange from `elk-api` and the worker script URL); `arrangeGraph` stays pure and takes the layout function, which Node tests supply from the bundled ELK. A worker that fails to load or throws rejects the pending layout and is dropped, so the document lock is released and the next Arrange starts a new worker.

Monarch string states continue across lines, and completion/hover literal guards preserve preceding-line lexical context. Monaco providers are disposed on cleanup and restricted to their own model, so nested editors do not contribute duplicate suggestions to each other. `useArcLanguageSupport` registers its providers once per model, and once more when the function catalog arrives, and reads the latest variables from a ref: every graph edit creates a new variables array, and a registration change makes Monaco restart an open suggestion list. When variable names or roles change, semantic colors refresh through the token provider's `onDidChange`, and `refreshOpenSuggestions` re-queries an open non-`@` suggestion list (Monaco's public `editor.action.triggerSuggest` does nothing while a list is visible). `InlineExpressionEditor`'s own effect still opens a list when a late scope or catalog makes a hidden prefix match. `useArcLanguageSupport` requires an explicit expression, node or script context: only script context enables module templates, while node context retains declaration semantics and function/Formula completion. The inspector registry must cover every `NodeType`. Reuse the existing value-binding controls for variable/constant/expression selection and string escaping. `domain/valueBinding` owns allowed constant types, literal compatibility and comparison type inference; mode switches preserve compatible values, and undeclared comparison operands never imply NUMBER by default. `domain/expressions` owns ARC literal syntax: string, number and array literals and the server's whitespace trim. It must accept exactly what `ExpressionParser` tokenizes; `tests/unit/literal-cases.ts` records the server's verdicts. A value binding infers its editor when it opens. `useEditingPin` then keeps the editor the user is typing in, including partial text, until the value-source menu, the Builder/Expression toggle or a change made elsewhere chooses again. Parameter mappings are read with `ownValue` and written with `withBinding`, so parameter names such as `__proto__` stay ordinary keys.

`useArcEditor` owns the mounted model and diagnostic markers, including diagnostics received before Monaco finishes loading. Every Monaco host takes its options from a module-level preset through `useEditorOptions(preset, readOnly, ariaLabel)`, so `updateOptions` runs only when the read-only flag or the label changes: a new options object per render made every editor write the page-wide configuration and, through the object-valued `quickSuggestions`, fire a global change for each mounted model. Catalog insertion, outline navigation and problem navigation are separate studio regions. An insertion that starts with a read (a Reuse card, a published Formula) captures the editor's text version and selection at the click (`captureEditorState`) and inserts only while both are unchanged (`unchangedSince`); a change reports "The code changed while the rule loaded" on the card, and the repeated clicks of a double or triple click are ignored (`useLibraryInsertion.onCardClick`). Module snippets declare cursor/end placement independently of their display name. Dynamic ARC literals must be escaped for Monaco snippet syntax after ARC/JSON quoting: `snippetStringLiteral` quotes and then escapes text, and `escapeSnippetText` escapes ARC code that is already built. Actual argument tab stops remain executable. Placeholders for required values come from `domain/placeholderLiterals.ts` (type-correct: `0`, `"value"`, `false`, `[]`, `$OBJECT()`), shared by Formula-call and Reference snippets; value-binding constant defaults reuse them for NUMBER, BOOLEAN and ARRAY. `reuseNodeId` bounds the rule-ID part of a generated Reference node ID so the ID stays within 80 characters. Outline navigation locates a declaration with `nodeDeclarationOffset`, which follows the backend scanner's comment, string and statement rules and compares IDs case-sensitively. Library cards insert through `useLibraryInsertion`: one pending read per library, a new choice aborts the previous one, and the loading card is disabled. Pending reference-insertion reads abort on unmount and consult the current draft/read-only state on completion.

`useRowIdentities` gives input parameter rows (`useInputParameterRows`) and Transform field rows their UI-only identity across immutable edits; neither array index, array length nor an editable name is a stable component key. It hands out one instance per component, so callbacks built from it keep their identity. Transform field and Switch case rows are memoized components (`TransformFieldRow`, `SwitchCaseRow`) whose callbacks are node-scoped functional updates on `onDefinitionChange`, and `useNodeVariables` returns the previous `variables` array while the options are equal, so a keystroke in one row renders that row alone. The variables read is keyed by `scopeGraphKey` (input names, node IDs and kinds, stored result names, Switch case IDs and connections), which is what `BranchScopes` reads, so label, expression, default and position edits keep the scope and send no read; `/api/variables` checks structure only, so such a read never fails for a content problem. Removing an input must discard only its raw JSON buffer/validity and keep other rows' unfinished edits and focus. Changing an input's type explicitly resets its default editor. Invalid JSON or numeric defaults remain in their mounted control; shared selection guards block canvas/outline changes, node-code entry and graph/code navigation until corrected or removed, and the shared `blockedByInvalidDefault(action)` produces the refusal messages. `shownView` never shows code while a default is invalid. Requesting the lazy node-code editor immediately locks its parent inspector through loading and closure. The request is dropped when its node leaves the draft, and a lazy node dialog offers Cancel until it is on screen, so a failed download releases the lock. Numeric defaults keep every entered digit: a value a double carries exactly becomes a number, any other value a `DecimalNumber`. The field blocks exactly the numbers the server's `Expressions.bound` rejects: more than 100 significant digits or a scale beyond ±100, both as written and without trailing zeros; a zero's scale counts as written, because it has no digits to strip. `NumericDefaultField` and `JsonField` keep the typed text while their own value returns through the draft and replace it only when a different value arrives. Node deletion retains at least one node, including drafts that currently have no Input; delete controls ask `canRemoveGraphNode`, which keeps the first Input node (the server's entry) and lets an extra Input go, and the result-name section appears for the kinds that store a result. Node code opens only while no command runs (`can.validate`), and an untouched node-code buffer follows its node's current code; Apply merges the fragment through `applyNodeFragment`, which takes only the node, its outgoing edges and (for the Input node) the parameters and keeps every unchanged local object. Value-provider typeahead uses `PagedAutocomplete` to load bounded catalog pages only while its dropdown is open and append the next page near the scroll boundary. Its fixed Caller/default choice is separate from server offsets and does not suppress loading, empty-search or retry feedback. Search and refresh identity invalidate old results; pinned source detail stays independent of catalog pages. The embedded source manager reuses the ordinary source editor, keeps its dirty state separate from the rule, and blocks closing while any source save is pending. The source editor registers navigation guards while it has unsaved edits or a pending save, so Back/Forward, typed URLs, graph/code switches and page unloads ask first. A failed manager chunk shows the lazy-boundary message with Close. Source-version selection retains only mappings accepted by the selected pinned contract through `bindSourceVersion`; hidden obsolete parameters must not remain in the submitted graph. Immutable pinned reads go through one page-wide cache (`app/pinnedReads.ts`, `PinnedReads<T>`, with the instances in `app/pinnedVersions.ts`): the pinned source version of every value-provider card, the pinned rule version of a Reference card or a Reuse card and Formula metadata share one request when they start together, keep only completed reads, and `forget(id)` drops a rule deleted or created again in this page (App's `forgetDeletedRule`, FormulaMetadata's incarnation check) and a source the manager may have renamed. A caller whose signal has already aborted starts no read, and a read every caller has left is never joined again. Formula metadata keeps its entries in a `PinnedReads` keyed by incarnation and reads a rule's identity (its summary by ID) through one of capacity 0, which shares a read in flight and keeps nothing, because a name can change. A card's mutable version list loads only once its Source version control opens.

Published Formula libraries, Reference node rule/version pickers and Value provider pickers share bounded server search and scroll-driven paging through `useAutocompletePages`. Formula libraries append cards in a scroll region, keep a keyboard Load more/Retry action, and fetch pinned input details only on insertion; appending a catalog page must not cancel that insertion. Reference node rule/version pickers combine search and paging in one autocomplete. Each search owns its page sequence; failed appends retain loaded options, and a retry uses the same offset. Selection stays independent of search results, so a filtered or off-page pinned version remains unchanged until the user selects another option. Rule version search filters numeric version text on the server before counting and paging. Preserve the first character typed into a closed dropdown and the user's current scroll position when options append; the [picker workflow tests](../frontend/tests/reference-picker.spec.ts) exercise both event-ordering cases. The [provider picker workflows](../frontend/tests/source-provider.spec.ts) also cover fixed choices, append retries and stale pages. The drawer and staged node dialog share `NodeIdentity`; the dialog header edits only its local draft until Apply and keeps a stable accessible dialog name while renaming.

`ExpressionField` lazy-loads an inline Monaco editor and the larger `ExpressionDialog` inside `LazyBoundary`: a chunk that fails to load shows an error in place of that editor, and the rest of the inspector and the draft stay editable. Both reuse Code studio's model-scoped completion providers, offering only in-scope variable names and no graph-module snippets. Inline editors enable the shared function catalog on first focus, retain incomplete expression text in the caller's draft, and use Tab for completion, snippet arguments and indentation. Monaco disables font ligatures, and the shared code-surface rule in `styles/base.css` disables them for code previews and JSON fields, so operators such as `==` display every entered character. `/studio/expression/check` parses syntax and reports dependencies, while the application layer validates direct Formula pins and arity without evaluating values or fetching source data; the dialog cancels obsolete checks and preserves its caller's draft until Apply. Runtime type checks still belong to preview/execution. Preview and the published API playground share a lazy JSON editor inside `LazyBoundary`, so a failed chunk leaves the page usable with its sample inputs; their controllers retain the raw buffer, including invalid JSON, and continue to own parsing and execution request identity.

### Styles

Styles remain global. They are split by owner, with no later override layers. `tokens.css` holds the values that several rules share by design: the 7–13px type scale (`--text-2xs` … `--text-2xl`), the fonts, color roles (`--color-*`), one color per node kind (`--node-kind-<kind>`, shared by canvas icons and library previews), and the sidebar and page widths. A color used once, or twice by coincidence, stays a literal in its rule. `--color-brand`, `--color-ink`, `--color-page` and `--color-surface` mirror the palette in `app/theme.ts`, so change both together.

Each view or component stylesheet owns its selectors. To change an element, edit the rule that owns its selector, or a token. Never add a later file or "pass" that restates another file's selector. The index keeps tokens and `base.css` first; the feature stylesheets were verified to give identical computed styles in reversed order. The responsive layers stay last, in their current order, because a later breakpoint file wins where two breakpoints set the same property: for example, `responsive/studio-wide.css` (≤1350px) sets the editor action buttons at the laptop and mobile widths too.

MUI component-wide sizing belongs in `theme.components.*.styleOverrides` (Alert, MenuItem and DialogActions sizes). When one component instance needs different values from MUI's styles, outrank MUI's single-class rule with a class pair such as `.routing-warning.MuiAlert-root`; MUI's styles load after the application stylesheet. `!important` remains only in three cases, each with a comment: React Flow's stylesheet loads later with the lazy editor route; MUI sizes the source JSON textarea with inline styles; and MUI's own rules are more specific for the notched outline hover/focus states and for the padding it removes when dialog content follows a title. Every application rule for a `.react-flow__` element either sets properties that stylesheet leaves alone or uses `!important`; keep it that way, or verify computed styles in both orders. Card widths come from `nodeWidth()` inline styles, and card font sizes change measured card heights, which routing, the minimap and Arrange use.

[`tests/style-cascade.spec.ts`](../frontend/tests/style-cascade.spec.ts) always checks the sources: no declaration may be overridden by a later rule with the same selector. A selector list may still be refined later for one of its members. It reported 68 such declarations in the previous stylesheets and none now. [`tests/style-node-kind-colors.spec.ts`](../frontend/tests/style-node-kind-colors.spec.ts) checks that library previews use each kind's canvas color.

To verify a stylesheet refactor, run the opt-in style specs against a disposable stack. [`tests/style-equivalence.spec.ts`](../frontend/tests/style-equivalence.spec.ts) records the computed style of every element in 45 UI states (the library, editor graph and code views, every inspector kind, the node dialogs, the Test panel, sources, the API playground and the docs page) at up to seven viewport widths, plus forced `:hover`/`:focus` states. API responses are replayed from a recording, so text and layout repeat exactly. Set `ARC_STYLE_SNAPSHOT_DIR`, record the API responses on the old build with `ARC_STYLE_HAR=record`, record the old build with `ARC_STYLE_LABEL=before`, rebuild, and rerun with `ARC_STYLE_BASELINE=before`: any changed value fails. `ARC_STYLE_LIVENESS=1` lists declarations that never win the cascade in any recorded state. The second test in `style-cascade.spec.ts` statically compares two `src/styles` trees parsed by Chrome, with tokens substituted and shorthands expanded (`ARC_STYLE_CASCADE_BASELINE`). Both opt-in comparisons skip unless their environment variables are set. Record mode creates fixture rules, so never point it at a working database.

## Design choices

The concrete SOLID applications are single-purpose services and forms, source strategies open to registration, substitutable repository/source contracts, narrow engine ports, and constructor-injected dependencies. The patterns used here are Repository, Strategy with a registry, Adapter, a request-scoped Decorator, and a reducer for document transitions. They address actual change points; there is no generic repository framework, event bus, or class hierarchy for every node. Node kinds are data on both sides: the backend's `NodeKind` enum with exhaustive switches, and the frontend descriptor `domain/nodeKinds.ts`.

`RuleNode` is not a discriminated union. The schema-1 graph JSON does not enforce field ownership: the server accepts and round-trips any node field on any kind, and unfinished drafts carry null or absent kind fields. Per-kind types would therefore still need the same null checks while claiming a precision the payload lacks, and the generic `patch(Partial<RuleNode>)` edits, staged form merges (`nodeFormDraft`) and `patchGraphNode` would need per-kind patch types and a correlated dispatch in the inspector registry. Exhaustiveness is enforced instead by `Record<NodeType, …>` tables and exhaustive switches.

These boundaries are maintenance rules, not a claim that every class is permanently complete. Keep grammar, expression execution and graph planning cohesive within their owners; split further only when a new independent responsibility appears, not based on line count alone.

### Architecture check

`scripts/check_architecture.py` checks declared imports and string literals, not reflection or fully qualified calls; behavioral tests and code review remain necessary. `scripts/check_architecture_test.py` runs each rule against probe files and the current tree.

- Java packages import only the ARC packages below them in the [backend table](#backend-boundaries): `model` and `error` import no other ARC package and no framework; `engine` may import `model` and `error`; `source` adds `engine`; `rule` adds `source`; `persistence` and `api` add `rule` but not each other. `api` never imports a repository, and SQL (`java.sql`, Spring JDBC) stays in `persistence`. Only the Spring composition root `ArcApplication.java` is exempt; any other file outside these packages fails as an unknown package until it is added to `ALLOWED_JAVA` and the backend table.
- Engine features import only their own package and these siblings or root contracts: `expression` → `Identifiers`, `ExecutionDeadline`, `Limits`, `ValueText`, `ValueBounds`; `graph` → nothing; `validation` → `graph`, `expression`, `Identifiers`, `InputTypes`, `RuleResolver`, `Limits`; `script` → `expression`, `validation`, `Identifiers`, `InputTypes`, `Limits`; `execution` → `graph`, `validation`, `expression`, `Identifiers`, `InputTypes`, `RuleResolver`, `SourceReader`, `ExecutionDeadline`, `Limits`, `BoundedCache`. Root `engine` classes, the shared contracts, import each other, `model` and `error`, never an engine feature.
- From the rest of `source`, providers (`source.http`, `source.lookup`) import only `SourceAdapter`, never the source application services.
- Outside `dev.arc.model`, no Java string literal (comments stripped) may spell a node type exactly (`"INPUT"` … `"OUTPUT"`), start with `case:`, or hold a regex alternation of kinds or of `next|true|false`; and a handle literal (`"next"`, `"true"`, `"false"`, `"default"`) may not be compared (`equals`, `equalsIgnoreCase`, `Objects.equals`, `==`, `!=`), used as a `case` label or collected (`Set.of`, `Map.of`, `List.of`). Use `Node.kind()`, exhaustive switches and `Handles`. The legitimate exceptions (`$SWITCH`, the boolean literals and reserved words) are allowlisted by file and literal, each with its reason.
