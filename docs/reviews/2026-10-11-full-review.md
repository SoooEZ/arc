> 中文说明：这是 2026-10-11 对整个项目（前端和后端）做的一轮 review，目标是找 bug，并检查模块化、文件位置与大小、可复用、可扩展和渲染/后端性能。评审在 `2cccaa0` 上进行，16 个角度共提出 76 个候选，去重后 69 项逐条验证（41 项 CONFIRMED、28 项 PLAUSIBLE，没有被直接推翻的），然后按你的"全修"要求全部处理。修复分五个阶段提交在 `fix/full-review-2026-10-11` 分支：A（后端求值、作用域、表达式、ARC Script 与校验）、B（编辑器、检查器、画布与规则库）、C（请求、存储、数据源与 smoke 脚本）、D（Code studio、语言层、数据源与镜像检查）、E（把所有编辑器共用的 Monaco/ARC 语言层从 `features/studio` 移到 `features/language`），最后是文档。每个 bug 都有修复前会失败的回归测试；结构性改动保留原有断言。有几项核实后只改文档或保持现状，原因写在"Kept with reason"一节。行为变化列在 [API 参考](../api.md#behavior-changes-from-the-2026-10-11-full-review) 和 [studio 指南](../studio.md#behavior-changes-from-the-2026-10-11-full-review)，新的和修订的规则在 [review lessons](../review-lessons.md)（B36–B38、F40、F41 和两条可维护性规则）。

## Scope and status

- Reviewed: `main` at `2cccaa0`, the whole project: `backend/src`, `frontend/src`, `scripts/` and the documentation, for bugs, readability, modularity, file placement and size, reuse, extensibility and render/backend performance.
- Method: six line-by-line area scans, a removed-behavior and contract audit of the last two commits and the `AGENTS.md` contracts, a cross-file contract tracer, language pitfalls, a wrapper and cache audit, reuse, simplification and structure, frontend render cost (measured in a production build), backend hot paths (measured against disposable PostgreSQL), altitude and extensibility, and conventions. 76 promoted candidates, 69 verified one by one with a probe, a measurement, a browser reproduction or a disposable stack; every candidate kept its verifier's corrections (several were narrowed or downgraded with measured numbers). The IDs below are the verification IDs.
- Status: every finding is handled. Phase commits on `fix/full-review-2026-10-11`: A (`557ad74`, evaluation, scopes, expressions, ARC Script and validation), B (`eab91ce`, editor, inspector, canvas and library), C (`dfe853d`, requests, storage, sources and smoke checks), D (`316d182`, Code studio, language layer, sources and mirror checks), E (`47f2619`, the shared language layer moved out of `features/studio`), then the documentation. Each bug fix has a regression test that failed before the change; structural changes keep the existing assertions and add the tests that were missing. The four streams were implemented in parallel worktrees and merged here; the merged tree was verified again as a whole (see [Verification](#verification)).
- File-size verdict, as asked: no file needed splitting for size alone. `useRuleDocument.ts`, `CodeStudio.tsx` and `sourceDocument.ts` held separable policies and lost them (the command lock and the delete command, the JSON view, the HTTP policy mirrors); `GraphExecution`, `DefinitionShape`, `JdbcRuleRepository`, `ArcScriptNodeParser`, `ExpressionRuntime`, `edgeRouting.ts` and `nodeKinds.ts` are cohesive single-owner files and stay whole.

## Kept with reason

- **S8** `features/editor/usePreviewExecution.ts`: the type-only back edge from the execution views to the editor is documented and deliberate; moving the hook would not remove it (`ReferenceTarget` still comes from the editor's types). Unchanged.
- **CV1** `useRuleDocument.ts` dirty flag: the unsaved draft is reported through the workspace's dirty flag by design (lesson F23); `frontend/AGENTS.md` now names the exception. No code change.
- **S7** `ExcelFunctionAdapter.checkArgumentBounds`: argument bounds have two homes by design (regex work in `ExcelMatchingWork`, size and pairwise work in the adapter); the maintenance guide now names both. No code change.
- **EB4** index: the proposed `(updated_at DESC, id)` index was measured to help only the unfiltered sort and to slow a no-match search; the `strpos` rewrite was applied instead.
- **EB8** pointer semantics: the whole response body is still bounded (no behavior change); bounding only the value the JSON Pointer selects is recorded as an option for a later decision.
- **R6** eviction order: the preview cache keeps its documented first-in, first-out order instead of adopting the LRU `PinnedReads`, which would change the contract for no reachable staleness.
- **A6-2** API: the Reuse pane shows the edited rule's card disabled instead of adding an `excludeId` catalog parameter, so the two pickers agree without an API change.
- **AL1** boundary: `api/` cannot import `domain/nodeKinds` under the architecture rule, so the guard is a per-card boundary and a kind check at the source editor's selection, not a parse at the HTTP boundary.
- **A1-4** constants: the analysis caps stay in `BooleanConditions`, because the dependency map forbids `engine.graph` from importing `Limits`.
