## Confirmed defect fixed

**P2 — A valid large graph could render code that the editor could not rebuild. Confidence: 100.** A graph with 60 formula nodes containing 1,900-character string literals passes graph validation and fits the HTTP request limit. Its generated ARC Script exceeds the former 100,000-character parser bound, so switching to code and rebuilding fails even though the graph itself remains valid. [Original parser guard](https://github.com/SoooEZ/arc/blob/c671c5469d6016065c217d4d31d8da086e3c1661/backend/src/main/java/dev/arc/engine/ArcScriptParser.java#L53-L55).

The parser now accepts up to 1,048,576 characters. The separate HTTP limit remains 1 MiB of encoded request bytes, including JSON escaping and UTF-8; this does not make every 1 MiB source string transportable. Graph, node, expression, value, recursion and execution limits remain unchanged. The regression fails with the old numeric bound restored in an isolated source copy and passes with the fix. A real HTTP validation/render/build round trip covers the same large graph, and oversized embedded source still returns diagnostics without a definition.

No other defect met the review's high-confidence threshold. The ownership changes below are maintainability improvements, not additional bug claims.

## Ownership and readability changes

- `engine.expression` owns parsing, execution and functions. `FunctionCatalog` now assembles capabilities and checks arity; ARC builtin specifications, typed Excel help and Excel categories have separate owners. Metadata is no longer decoded from positional string arrays. The catalog's 432 entries, order, help, snippets, origins, supported flags and arity behavior were compared against the starting snapshot and retained as golden contracts.
- `engine.script` separates document/input grammar from node grammar and strict literal decoding. Scanner and renderer stay cohesive. Whole-document and single-node editing still enter through `ArcScript` and use the same grammar and canonical serialization.
- `engine.graph` separates deterministic topology, branch-sensitive scope inference and bounded Boolean decision diagrams. `GraphPlan` exposes read-only topology/scope queries rather than mutable public collections. Branch analysis retains its original algorithm and limits, with clearer local names and private internal state.
- `engine.validation` separates incomplete draft shape, executable graph validation and editor diagnostics. `Validator` coordinates those operations; shared node checks continue to produce navigable errors. Validation ordering and diagnostics remain intact.
- `engine.execution` separates the stateless `Engine` facade, one-call `GraphExecution` session, variable provenance/merge policy in `ExecutionScope`, and source parameter resolution in `Parameters`. Nested calls retain the shared trace, recursion guards and source budget. Explicit loops now explain why an ancestor's value is superseded and why concurrent sibling writes conflict.
- The root `engine` package retains narrow resolver/reader contracts and the shared `Identifiers`/`InputTypes` policies. Expression parsing and source validation no longer call static helpers on the graph validator.
- `SourceService` owns version commands and transactions; `SourceExecutionService` owns typed reads and provider dispatch. HTTP and lookup implementations live under `source.http` and `source.lookup`. Static binding checks use the repository contract without depending on the command service. The JDBC adapter provides a direct latest-version lookup using the persisted version pointer and reuses its row mapper.
- Tests follow their owning packages. Shared graph fixtures have a dedicated test-support class instead of importing helpers from another test class. The architecture guard now also rejects reverse dependencies between engine features and provider imports of source application services.

## Compatibility

HTTP routes, payload fields/statuses, graph JSON, pinned references, ARC Script syntax, draft revisions, publication transactions, source fallback/override behavior, explicit nulls, decimal arithmetic, fan-out/joins and single/multiple Output results are preserved. Applied Flyway migrations and dependency/build manifests are unchanged this round.

Internal Java imports intentionally changed. Embedded Java callers would need the new feature package names, `GraphPlan` accessors, `Identifiers.isValid` and `InputTypes.check`; `SourceExecutionService.Test` replaces the old source command service's test request record. All repository callers were migrated. These Java types are not a versioned external SDK; their serialized HTTP shapes remain compatible.
