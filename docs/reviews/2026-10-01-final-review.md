# Final full review: findings and fixes (2026-10-01)

> 中文说明：这是 2026-10-01 对整个项目（前端和后端）做的最后一轮 review，目标是找出并修复 bug，同时让代码易读、模块化、可扩展，文件放在该在的目录里，方便阅读和查找。评审在 `cae51a5` 上进行，共提出 127 个候选，去重并逐条验证后：49 组 bug 全部修复，每组都有修复前会失败的回归测试；19 项结构问题已整理；9 项效率问题中 6 项已修复、3 项暂缓并写明原因；另有 9 项经核实保持现状，也写明了原因。其中有两项是上一轮后端 review 引入的回归（`$ERROR.TYPE` 改为仅供参考、分支分析的测试编号），本轮已撤回或补救。修复分四个阶段提交在 `fix/final-review-2026-10-01` 分支：A（后端求值、ARC Script、请求与存储）、B（前端编辑器、导航、对话框、数据源）、C（结构、共享缓存、渲染开销）、D（文档）。

## Scope and status

- Reviewed: `main` at `cae51a5`, the whole project: `backend/src`, `frontend/src`, `scripts/` and the documentation, for bugs, readability, modularity, extensibility and file placement.
- Method: line scans of every module, then passes for reuse, placement, simplification, conventions, removed behavior, cross-file contracts, pitfalls and efficiency, and an adversarial pass over the backend review's own changes. Each candidate was verified with a probe, a mutation, a browser reproduction or a disposable stack before it was kept. The IDs below are the verification IDs; a row that lists several IDs merges findings of the same defect.
- Status: every bug below is fixed. Phase commits: A `a62b61d` (evaluation, ARC Script, requests and storage), B `c3338f8` (editor, navigation, dialogs and sources), C `155850c` (structure, shared caches and render costs), `cbe658d` (the web smoke check under strict request JSON, found while verifying), D (documentation). Each bug fix has a regression test that failed before the change; structural changes keep the existing assertions and add the tests that were missing. Behavior changes are listed in [the API reference](../api.md#behavior-changes-from-the-2026-10-01-final-review) and [the studio guide](../studio.md#behavior-changes-from-the-2026-10-01-final-review); new and refined rules are in [the review lessons](../review-lessons.md) (B31–B35, F38, F39).

Three were left as they are:

- EF-3: a version switch reads the rule, then the version. The rule read is the contract that refreshes the draft when the user returns from a published version ([session test](../../frontend/tests/rule-session.spec.ts)), and the version load belongs to the document hook, which owns its lock and retry; reading both at once would move it out.
- EF-6: a Reference node's inspector and a Formula call's hover read the whole rule for its current name and incarnation. No summary-by-ID endpoint exists, and adding one is an API addition; the reads happen once per inspector mount or hover, never per keystroke, and reads in flight are shared.
- EF-7: the node dialog reads `/variables` again for its own staged copy. The dialog's scope follows its own edits, and until the read answers its controls stay neutral (lesson F10), so no result is wrong; a page-wide scope cache would be a later efficiency step.

## Kept as they are

- A3-7: a lone CR in ARC Script. Monaco turns it into the model's line ending on load and paste, so editor builds never send one; API clients get lines counted at `\n`, and a comment's line breaks, CR included, start new notes as documented (lesson B12).
- A3-8: `ArcScript.parse` is public and used only by tests. It is the fixture parser of nine test classes, and moving it would churn them without a readability gain.
- A1-6: `ISREF` and `AREAS` are executable although ARC has no references. Making them reference-only would stop published versions that mention them from compiling (lesson B31); they answer `FALSE` and `#VALUE!` deterministically.
- A1-7/D1-6: `$TO_NUMBER` and number lookup keys read Unicode decimal digits. `BigDecimal` reads them as their values, so no number is wrong, and refusing them would turn published results into errors.
- A6-5: switching an ARRAY binding that holds `['a']` to Constant starts from `[]`. This is the documented contract (lesson F16, the shared literal table): only JSON arrays become constants.
- A4-4: source parameters and rule inputs resolve with similar rules, but their contracts and messages differ (call arguments versus rule inputs); one helper would need flags.
- CV-4: the draft-shape size checks walk expressions apart from compiling, and messages for a case or field do not repeat its name. The shape pass bounds sizes before anything is parsed, ARC Script locates the case or field statement, and changing the messages would change HTTP payloads without fixing a wrong result.
- S-8: the focus hook's naming, resolved by the B2-1 rewrite (`requestedFocus` and the derived `pendingFocus`).
- A7-2, refuted: `formulaSnippet` writes `null` for a sourced optional input before a later argument. An explicit null skips the source by design, and ARC has no syntax for skipping a middle argument ([studio guide](../studio.md)).
- Duplicates: AL-1 is A1-1; A4-1, C2-2 and E-1 are B1-1; A5-1 is B2-1; C1-2 is A6-2; CV-8 is R-8.
