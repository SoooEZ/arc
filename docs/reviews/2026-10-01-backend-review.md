## Correction during the fix

The first fix of V12 made `ExecutionDeadline.within` report any ARC error that arrives after the deadline as the deadline. `scripts/smoke.py` then failed: `$COUNTIF`'s numeric-text guard spends about 150 ms before its `422`, so with `"timeoutMs": 100` the answer became a `504` that depended on the host's speed. Commit `85d07fe` reverted that and removed the deadline check from the source-mapping position instead: evaluation is CPU work that checks the deadline itself, so a late value error is still the expression's answer, while a source read, which the deadline cancels, reports its late failure as the deadline.

Two existing tests parked once (`LockSupport.parkNanos`) to make a source value arrive late; a park can return early, and the full suite then failed now and then. Both now wait until the deadline has passed.
