## Confirmed defects fixed

1. **P2 — Selecting a source version could retain hidden obsolete parameter mappings. Confidence: 100.** If v1 declares `customerId` and v2 replaces it with `accountId`, the old UI changed only the pinned version. It stopped displaying `customerId` but continued submitting its mapping, which backend validation rejects. The source-version operation now retains only mappings accepted by the selected contract. The regression uses real versioned source definitions, preserves an unchanged mapping, fills the renamed parameter, previews with a caller override and saves the resulting graph. No external HTTP service is called. [Original version update and mapping UI](https://github.com/SoooEZ/arc/blob/c671c5469d6016065c217d4d31d8da086e3c1661/frontend/src/components/SourceBindingEditor.tsx#L85-L120).

2. **P2 — Input deletion/type changes could transfer or retain invalid JSON editing state. Confidence: 100.** Input cards and validity were keyed by array index. Deleting the first ARRAY input could move its unfinished buffer to the next parameter, or clear the visible error while the hidden validity flag continued to block Save. Switching ARRAY to OBJECT also reused a default-value editor even though the type change resets the default. Cards now use stable UI-only row identities, and default editors reset on declared-type changes. Tests preserve other rows' unfinished text and rename focus, verify invalid Save produces no write, and verify successful persistence after deletion, correction or type change. [Original indexed cards and validity ownership](https://github.com/SoooEZ/arc/blob/c671c5469d6016065c217d4d31d8da086e3c1661/frontend/src/features/editor/inspector/InputFields.tsx#L43-L114), [original JSON buffer lifecycle](https://github.com/SoooEZ/arc/blob/c671c5469d6016065c217d4d31d8da086e3c1661/frontend/src/components/JsonField.tsx#L17-L29).

3. **P2 — Code-studio reference insertion interpreted rule names as Monaco snippet syntax. Confidence: 100.** Legal labels such as `Discount $100` or text containing backslashes/`${1:literal}` were JSON-quoted but then interpreted a second time by Monaco. The inserted label changed or became a tab stop. Dynamic literals are now escaped after ARC/JSON quoting; intended result/target placeholders remain editable. The browser regression inspects the real Build request after insertion and keyboard edits. [Original snippet construction](https://github.com/SoooEZ/arc/blob/c671c5469d6016065c217d4d31d8da086e3c1661/frontend/src/features/studio/snippets.ts#L27-L39).

## Maintainability changes

These are ownership improvements, not additional bug claims:

- Feature pages and controls moved from the generic `components` directory into `features/editor`, `studio`, `expressions`, `execution`, `sources` and `library`. Shared controls remain independent of feature/application orchestration, enforced by the architecture check. All callers and tests were migrated; obsolete paths and the unused aggregate API facade were removed.
- Editor composition delegates graph commands/layout, focus, toolbar/menu/outline, version loading and export to their owners. `documentState` remains the authoritative draft/code/trace state. No second graph store or global event bus was introduced.
- Studio library, outline and problems are separate components. `useArcEditor` owns mounted-model diagnostics and common editor configuration; providers remain model-scoped and disposed. Reuse reads abort on unmount and consult current editability/definition. Module insertion placement is explicit metadata rather than a comparison against display labels.
- Execution request state stays in the shared cancellable hook. Published-version orchestration and static API documentation are separated from the page, while preview result/error components own trace and error-location presentation.
- Parameter cards/default values and row operations have separate responsibilities. The Input inspector loads the source catalog once for all cards. Constant classification remains pure domain code, and typed constant UI is separate from binding-mode selection.
- Workspace header and theme moved beside app composition. Shared reference-navigation types are imported from the feature contract, not a dialog component.
- The 3,634-line stylesheet became an explicit entry point and 28 named style files, largest 332 lines. Parsed CSS verifies every rule, declaration and cascade position is preserved after formatting, including responsive blocks and later overrides.

Representative file sizes, before → after: Editor 450 → 340, CodeStudio 329 → 155, API page 347 → 197, TestPanel 281 → 158, Library 314 → 202. These counts describe the result; extraction was justified by independently changeable responsibilities. The remaining 340-line editor is page composition, and the 269-line routing algorithm remains cohesive. No arbitrary hard line limit or forwarding-only component was added.

See [the updated ownership and extension guide](../maintaining.md#frontend-boundaries).
