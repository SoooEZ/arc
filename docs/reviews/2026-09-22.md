## Confirmed defects

1. **P1 — Saving a historical version through the keyboard could overwrite the current draft. Confidence: 100.** Opening a published version substituted its definition but retained the latest revision. Monaco still registered the Save command, and the controller did not check read-only state, so Ctrl/Cmd+S could successfully PUT historical content over the draft. The command boundary and Monaco action now both enforce read-only state. A browser regression verifies that history makes no write and preserves draft/revision, while the ordinary draft shortcut still works. [Original save command](https://github.com/SoooEZ/arc/blob/c671c5469d6016065c217d4d31d8da086e3c1661/frontend/src/features/editor/useRuleDocument.ts#L191-L205), [keyboard action](https://github.com/SoooEZ/arc/blob/c671c5469d6016065c217d4d31d8da086e3c1661/frontend/src/components/CodeStudio.tsx#L215-L222).

2. **P2 — Graph constant editing changed Unicode and control-character values. Confidence: 100.** `literalText` decoded only `n/r/t`; a saved `"\u0041"` displayed `u0041` instead of `A`, and editing that field wrote back a different value. The same affected `\b` and `\f`. Standard JSON encoding/decoding now owns escapes, with a small normalization step preserving ARC's single quotes and legacy unknown escapes. Malformed Unicode remains an expression error rather than becoming a misleading constant. [Original decoder](https://github.com/SoooEZ/arc/blob/c671c5469d6016065c217d4d31d8da086e3c1661/frontend/src/domain/expressions.ts#L10-L20).

3. **P2 — A failed historical-version read displayed the current draft as that version. Confidence: 100.** A failed version GET still cleared loading, revealing the initial draft under the immutable-version label, including test and export controls. Explicit loading/ready/failed state now gates the editor and derived requests. Failure offers retry or return to the current draft; reference-modal navigation remains available. The browser regression checks a 503, absence of graph/code/test/export and wrong-definition requests, returning to the draft, and successful retry with the actual historical result. [Original failure transition](https://github.com/SoooEZ/arc/blob/c671c5469d6016065c217d4d31d8da086e3c1661/frontend/src/features/editor/useRuleDocument.ts#L85-L101).

4. **P2 — HTTP source policy blocked ordinary public addresses around reserved ranges. Confidence: 98.** The handwritten IPv4 check used only two bytes for several ranges, blocking entire `/16` networks instead of intended `/24` blocks. For example, `192.0.78.24` was blocked; a normal allowlist entry did not correct that because private-address exceptions are distinct. The extracted destination policy names the exact protocol/documentation/benchmark ranges and tests both sides of their boundaries. A new regression failed against the old implementation before the fix. [Original checks](https://github.com/SoooEZ/arc/blob/c671c5469d6016065c217d4d31d8da086e3c1661/backend/src/main/java/dev/arc/source/HttpSource.java#L97-L106), [IANA range definitions](https://www.iana.org/assignments/iana-ipv4-special-registry).

5. **P2 — Interrupting the Arrange viewport animation could permanently lock draft commands. Confidence: 100.** Full browser testing exposed a timing-dependent failure: React Flow's animated fit resolves only on D3's `end`, while user interaction can interrupt it without that event. `layout` awaited the unresolved promise inside `runTask`, leaving Save/Publish/Arrange disabled. Arrange now fits the viewport immediately (`duration: 0`), keeping a cancelable visual animation out of the draft-command lock. A regression interrupts the first fitted frame through the actual wheel handler and verifies zooming, command recovery and persistence of the arranged positions. It failed against the old animated implementation before the fix. The existing edge-selection test also waits for Arrange to complete before measuring its click coordinates. [Original awaited animation](https://github.com/SoooEZ/arc/blob/c671c5469d6016065c217d4d31d8da086e3c1661/frontend/src/components/Editor.tsx#L174-L190).

## Backend changes and their maintenance benefit

- **Separate grammar from execution policy.** `ExpressionParser` owns tokens, precedence and lexical dependency analysis. `ExpressionRuntime` owns operators, lazy calls and collection evaluation. The existing `Expressions.compile/evaluate` and compiled `variables/evaluate` entry points remain the callers' interface. Changing a lazy function no longer requires navigating parser internals; changing literal syntax no longer touches iteration or scope execution.
- **Make evaluation state explicit.** Each evaluation receives a context and budget, shared by its nested collection scopes. Compiled code contains no mutable execution state. This removes ambient `ThreadLocal` state and prevents an embedded, reentrant evaluation from resetting its caller's work counter. Tests cover reuse, concurrency, recovery after failure and reentrancy. Raw `Expr` access and public construction of `Compiled` were internal implementation leaks with no repository callers; callers now obtain compiled code through `compile`.
- **Use existing Jackson for string decoding.** A private configured `JsonFactory` replaces the manual Unicode/control escape loop. The options preserve existing ARC single quotes, unknown escapes and raw controls; HTTP and stored JSON parsing are unaffected. Compatibility tests include escaped delimiters, malformed Unicode, surrogate pairs and isolated UTF-16 surrogates.
- **Reuse validated intermediate results.** `Engine` consumes the `GraphPlan` created by `Validator.plan`; source-dependency checks reuse the compiled expression they just validated. This removes the immediate duplicate topology construction and compilation. The HTTP application layer still performs graph/source-contract checks; this is not a global cache or a claim that each request plans only once.
- **Separate destination policy from HTTP transport.** `HttpDestinationPolicy` directly implements HttpClient5's `DnsResolver`. `HttpSource` retains request construction, cancellation/deadlines and bounded response handling. The constructor and `validate/resolve` entry points remain compatible. Configuration checks perform no network reads; destination checks still happen when establishing the connection.

These are focused concrete collaborators, not a new service-locator or plugin framework. JDBC transaction ownership, immutable version pins, per-execution source limits, graph/ARC Script JSON, decimal arithmetic and public HTTP contracts remain intact. No migration, new runtime dependency or dependency-version change was introduced.

## Package decision

[The library assessment](2026-09-22-library-options.md) records versions, license sources and compatibility evidence for EvalEx, JEXL, exp4j, POI, Jackson and HttpClient. EvalEx is the closest Dentaku-style option, but its default coercion, case-insensitive dependencies, `COALESCE` evaluation and array behavior would change existing ARC rules. Replacing the language now would require substantial adapters and compatibility work. Candidate engines were inspected statically, not benchmarked or executed.

This pass instead removes handwritten string decoding using existing Jackson and uses the existing HttpClient extension point directly. POI continues to implement context-free Excel functions. A future engine migration needs a differential compatibility corpus and an explicit language-version path for any intentional semantic change; library popularity alone is not sufficient evidence.
