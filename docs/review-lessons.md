# ARC review lessons for future changes

This is the reusable guidance extracted from ARC's completed reviews. It records failures that actually occurred, the decision that prevents each failure, and the existing regression coverage. Dated reports retain the original evidence and severity; this document is the entry point for future implementation and review.

## How to use

Before generating or changing code, read the sections relevant to the affected behavior and inspect their linked tests. Identify the authoritative state, compatibility boundary and failure path before choosing a component, hook, service or library. During review, check the actual caller and observable effect; matching a checklist or passing a build alone does not establish correctness.

For a regression, prefer an observable test that fails before the fix. For a refactor, retain the existing assertions and contracts; do not regenerate fixtures merely to accept changed behavior. Run the affected checks from [the verification matrix](../AGENTS.md#verification), and report what was exercised. Unrelated sections do not require extra work or approval.

## Frontend failures

| Failure and trigger | Rule for new code | Regression coverage |
| --- | --- | --- |
| **F1 — Save erased newer edits.** A save/publish response replaced the whole document after the user changed the graph. | Carry the submitted snapshot into the acknowledgement. Advance the server revision and saved baseline, preserving later graph/code edits and dirty state. Staged node forms merge only their changed nodes, connections and input schema; reject conflicts and newly dangling connections while preserving unrelated edits and live positions. Enforce command coordination in the controller/reducer as well as the controls. | [Document transitions](../frontend/tests/unit/document.spec.ts), [save lifecycle](../frontend/tests/execution-lifecycle.spec.ts), [staged form merges](../frontend/tests/unit/node-form.spec.ts), [context menu and modal guards](../frontend/tests/node-context-menu.spec.ts) |
| **F2 — Source A overwrote source B.** A save, test or initial-list request finished after changing selection, reopening a source, or creating another source. | Separate catalog updates from open-document updates. Requests belong to a resource, selection session, version and relevant input buffer. Late completion must not overwrite another resource or newer edits. A reopened instance of the same source may reconcile a newer server revision/baseline while preserving its edits. | [Source transitions](../frontend/tests/unit/sources.spec.ts), [source editor races](../frontend/tests/source-editor.spec.ts) |
| **F3 — Old execution restored a result, trace or error.** Editing inputs/graph, changing trace or timeout options, or closing the panel cleared the UI, but a pending callback later wrote into it or its parent. | Execution identity includes the target, inputs, trace setting and timeout. Invalidate requests when any of these changes and on unmount. Abort obsolete work and guard completion with identity; clearing state or aborting alone is insufficient. Apply the same rule to node builds, diagnostics and reuse insertion. | [Execution lifecycle and option changes](../frontend/tests/execution-lifecycle.spec.ts), [stale diagnostics](../frontend/tests/resources.spec.ts), [reuse insertion](../frontend/tests/studio-refactor.spec.ts), [published Formula insertion](../frontend/tests/formula-calls.spec.ts) |
| **F4 — A historical version overwrote the draft through Cmd/Ctrl+S.** The UI hid Save while Monaco's command remained callable with the current draft revision. | Read-only checks belong at every mutation command entry point. Verify that forbidden actions make no write and do not change the server revision. | [Historical and draft keyboard saves](../frontend/tests/studio.spec.ts) |
| **F5 — Failed history loading showed the current draft as a published version.** A failed GET merely cleared `loading`, revealing data that belonged to a different version. Metadata refresh and history paging can likewise reset a selection or its edited inputs. | Use explicit loading/ready/failed resource states. | **F6 — Input deletion/type changes transferred or retained invalid JSON state.** Index-keyed cards moved an unfinished buffer to another row; changing ARRAY to OBJECT retained obsolete editor state. | Use stable UI-only row identities, separate from array index or editable parameter name. | **F7 — Selecting another source version submitted hidden obsolete bindings.** The dropdown switched the visible parameters but kept mappings no longer accepted by the selected version. | Treat selection as a domain transition: retain only compatible mappings, expose newly required inputs and persist the exact selected pin. Hiding a field must not leave an invalid hidden payload. | [Pinned source parameter mapping](../frontend/tests/frontend-refactor.spec.ts) |
| **F8 — Interrupting Arrange permanently locked commands.** A cancelable viewport animation never resolved, while Save/Publish/Arrange waited inside the document lock. | Keep optional visual animations outside mutation completion/locks. Do not assume a third-party Promise settles on cancellation. Preserve an immediate or explicitly settled completion path and test real user interruption. | [Interrupted viewport fitting](../frontend/tests/routing.spec.ts) |
| **F9 — Reused rule labels became Monaco snippet syntax.** Valid names containing `$100`, backslashes or `${1:literal}` changed during insertion. | Track every parser boundary. Quote dynamic ARC/JSON literals first, then escape those literals for Monaco snippets. The literal `$` in namespaced function calls also needs snippet escaping, including nested calls and calls inside default placeholders; intentional tab stops remain separate metadata. Completion ranges consume an already entered prefix once. Test the actual built source and keyboard editing, not just the generated helper string. | [Literal labels and editable placeholders](../frontend/tests/studio-refactor.spec.ts), [function prefixes, nested snippets and variable collisions](../frontend/tests/function-namespace.spec.ts) |
| **F10 — Disconnected nodes offered unavailable inputs.** The variable picker prepended every rule input despite an empty incoming scope from `/api/variables`, including during loading or failed reads. | Filter both input and computed-result choices through the authoritative node scope. Empty or pending scope must not become global input availability. Preserve existing expressions when a connection disappears, and keep input-source mappings' separate declaration scope intact. | [Variable choices](../frontend/tests/unit/document.spec.ts), [connections and delayed scope reads](../frontend/tests/available-variables.spec.ts) |
| **F11 — Equality looked like assignment while editing.** JetBrains Mono ligatures under `optimizeLegibility` rendered two entered equals signs as one long glyph even though the expression buffer still contained `==`. During the editor replacement, Chromium's native EditContext path also failed to deliver space and rapid key events to Monaco. Adding `$` as a completion trigger later offered function snippets inside strings/comments despite disabled quick suggestions there. | Disable programming ligatures in editable code and code previews. Keep the verified textarea input path and test rapid key entry, visible operator glyphs and the saved expression. A buffer-only assertion cannot detect the rendering failure. Guard string/comment tokens in the completion provider: trigger characters bypass quick-suggestion settings. Exercise completion and Tab through real key events; use a paste event for whole-document fixtures rather than assigning Monaco's accessibility textarea. | [Inline expression rendering, completion and saved text](../frontend/tests/inline-expression.spec.ts), [JSON typing and indentation](../frontend/tests/execution-json-editor.spec.ts), [literal dollar signs and completion triggers](../frontend/tests/function-namespace.spec.ts) |
| **F12 — Semantic providers existed but some editors stayed uncolored.** Monaco’s bundled all-features entry omitted document semantic tokens, and a second Switch editor requested tokens before its model was attached. | Load the semantic-token contribution actually used and register model-scoped providers after attachment. Return no tokens for unrelated models and dispose registrations on cleanup. Assert painted colors in multiple editors, not only classifier output; preserve strings, properties and collection-local shadowing. | [Rendered colors, multiple models and scope changes](../frontend/tests/expression-colors.spec.ts), [symbol roles and local scopes](../frontend/tests/unit/expression-symbols.spec.ts), [Formula colors and hover contexts](../frontend/tests/formula-context.spec.ts) |
| **F13 — Editing an inferred expression replaced its editor.** Clearing an Output expression or completing a literal caused value-source inference to switch to a variable/constant control, losing focus mid-entry. | Infer a mode when opening a value, then keep expression mode once the user edits its buffer. Empty, incomplete, variable-shaped and literal expressions remain editable until the user explicitly changes the value source. | [Output expression editing and Formula entry](../frontend/tests/formula-context.spec.ts) |
| **F14 — Library previews omitted most of a rule.** The synthetic preview drew only the first Condition and two immediate children, hiding further branches, joins and disconnected nodes. | Render actual topology and fit every node and valid connection. Cancellation is a lifecycle policy, not a generic wrapper to apply blindly. Reads, saves and source selection have different completion effects. Reuse the existing document reducers and request hooks where their contracts match; do not create a second draft store to simplify one component.

## Backend and serialization failures

| Failure and trigger | Rule for new code | Regression coverage |
| --- | --- | --- |
| **B1 — String values changed across editors and execution.** Both the original backend decoder and a later graph constant decoder mishandled `\uXXXX`, `\b` and `\f`. | Use the shared literal helpers and established JSON decoding. Preserve ARC's single quotes/legacy unknown escapes explicitly; reject malformed Unicode. Keep permissive literal-decoder configuration private so HTTP, persistence and source JSON remain strict. Exercise value fidelity across both frontend and backend, including surrogate pairs and control characters. | [Frontend literals](../frontend/tests/unit/expressions.spec.ts), [backend compatibility](../backend/src/test/java/dev/arc/engine/expression/ExpressionCompatibilityTest.java), [expression behavior](../backend/src/test/java/dev/arc/engine/expression/ExpressionsTest.java) |
| **B2 — Decimal remainder escaped as an internal error.** `1e40 % 3` caused `BigDecimal.remainder` to throw outside ARC's normal error/fallback handling. | Preserve arithmetic precision while translating expected arithmetic failures at the expression boundary. `IFERROR` and structured node/rule locations must receive the ordinary ARC error contract. Do not hide unexpected failures with a broad catch. | [Expression failures and fallback](../backend/src/test/java/dev/arc/engine/expression/ExpressionsTest.java), [node error locations](../backend/src/test/java/dev/arc/engine/execution/EngineTest.java) |
| **B3 — Minimum integer precision bypassed a limit.** `Math.abs(Integer.MIN_VALUE)` remains negative, so `ROUND(1, -2147483648)` passed an absolute-value bound. | Compare signed lower/upper bounds directly. Test minimum/maximum values and both sides of boundaries when validating sizes, scales or counts; ordinary small values do not prove a range check. | [Rounding limits](../backend/src/test/java/dev/arc/engine/expression/ExpressionsTest.java), [execution errors](../backend/src/test/java/dev/arc/engine/execution/EngineTest.java) |
| **B4 — Public HTTP addresses were rejected as reserved.** A two-byte check blocked whole `/16` ranges where only `/24` blocks were intended. | Name exact network ranges and test allowed as well as forbidden neighbors. Preserve the distinction between destination allowlists and explicit private-host exceptions. Keep configuration validation free of network reads and destination checks at connection-time resolution. | [HTTP destination boundaries](../backend/src/test/java/dev/arc/source/http/HttpDestinationPolicyTest.java), [real local HTTP behavior](../backend/src/test/java/dev/arc/source/http/HttpSourceTest.java) |
| **B5 — Generated data exceeded its consumer's limit.** Graph validation/rendering accepted a graph whose ARC Script exceeded the parser's old 100,000-character cap. Adding a Default Output suffix to a valid 160-character Switch label likewise produced an invalid node label. | Check limits across producer and consumer boundaries, including escaping and generated suffixes. Bound generated labels without splitting surrogate pairs. Distinguish source characters from encoded HTTP bytes. Test graph → code → graph with a realistically large valid definition and separately reject oversized requests. | [Script contract](../backend/src/test/java/dev/arc/engine/script/ArcScriptContractTest.java), [HTTP request bounds](../backend/src/test/java/dev/arc/api/RequestLimitTest.java), [studio HTTP round trip](../scripts/studio_smoke.py), [generated Default Output labels](../frontend/tests/unit/switch.spec.ts) |

For ordinary typed string controls, the user enters the string value; the shared binding helper creates the expression literal. Code mode still accepts explicit expression syntax. Monaco insertion introduces an additional parser boundary as described in F9; a universal “escape once” helper cannot represent both jobs.

## Earlier graph and navigation fixes

These failures are recorded in earlier commits, separately from the later review findings. Preserve their fixes when changing presentation or reorganizing components.

- **Error navigation needs the whole reference context.** Opening a referenced rule inside the modal and then navigating deeper/back could lose the runtime error locations. Carry rule ID, pinned version and the complete caller/child location path with the navigation session; a message or bare node ID is insufficient. Evidence: [reference error fix](https://github.com/SoooEZ/arc/commit/5ac381d814ef9b830778cc32772a7d1ef4fddca3). Coverage: [nested modal navigation](../frontend/tests/node-editor.spec.ts) and [nested runtime errors](../backend/src/test/java/dev/arc/engine/execution/FanOutTest.java).
- **Errors must not move graph geometry or inspector fields.** Diagnostic text and changing border widths moved card dimensions and handles; inline inspector alerts also pushed editable content when diagnostics arrived. Keep indicators in stable slots and show complete messages in overlays. Verify error appearance/removal alongside editing, drag and Arrange. Evidence: [stable diagnostic geometry](https://github.com/SoooEZ/arc/commit/941f4714b16ed03b386b3c8f5e6ba9eac888afca). Coverage: [node editor height assertions](../frontend/tests/node-editor.spec.ts), [stable inspector errors](../frontend/tests/inspector-header.spec.ts), [variable overlays and accordion geometry](../frontend/tests/inspector-sections.spec.ts), [edge routing](../frontend/tests/routing.spec.ts). The later F8 lesson supersedes that commit's awaited animation behavior.
- **UI measurements must survive without entering the saved graph.** Rebuilding React Flow nodes without their measured dimensions broke the minimap/geometry. Preserve measurement state for the canvas while excluding it from portable definitions and dirty-state comparisons. Evidence: [measurement preservation](https://github.com/SoooEZ/arc/commit/90bb33874a5878b1d99ceef987fdc8bfda82abb0). Coverage: [minimap and saved state](../frontend/tests/arc.spec.ts), [document semantic identity](../frontend/tests/unit/document.spec.ts).

## Maintainability lessons and contract guards

These are structural findings and compatibility requirements, not additional claims of production defects.

| Repeated maintenance risk | Decision to preserve | Existing evidence or owner |
| --- | --- | --- |
| Large files mixed grammar, execution, metadata, IO or unrelated UI lifecycles. Moving code alone could merely spread the same coupling. | Split around independently changing policies and migrate callers together. Keep cohesive algorithms together. Prefer typed records, named operations and short loops over positional arrays, nested ternaries or dense streams. Line counts and interface counts are observations, not acceptance criteria. | [Ownership map](maintaining.md), [architecture guard](../scripts/check_architecture.py) |
| A useful library appeared to replace handwritten code but differed in coercion, lazy evaluation, nulls, names or precision. | Check observable compatibility before substitution. Reuse existing Jackson, POI and HttpClient seams where appropriate. A new engine needs a differential corpus and an explicit version path for intentional changes to published rules; popularity alone is insufficient. | [Library assessment](reviews/2026-09-22-library-options.md), [expression compatibility](../backend/src/test/java/dev/arc/engine/expression/ExpressionCompatibilityTest.java) |
| Ambient evaluation state made reentrancy and reuse difficult to reason about. Resetting limits per child changes the contract; checking a deadline only after preparation allowed a slow child-definition read to be followed by another query after expiry. | Compiled expressions are immutable; each evaluation owns explicit context/budget. Nested collections and rules share operation/read limits and one monotonic deadline covering preparation and execution. Check before and after definition/configuration reads so an expired request cannot start later work; this does not interrupt JDBC already in flight. Preserve deadline status `504` through node error wrapping, source `DEFAULT` and expression `IFERROR`; fallback must not turn overall expiry into a result. Direct `@id:version(...)` Formula calls use the same graph session, including calls in source bindings and collection bodies; inactive lazy branches must not execute children. Disabling trace retention must not disable the step budget. Keep request values and counters outside shared compiled plans; any bounded shared plan cache is keyed by immutable ID/version pins. | [Concurrent, failed and reentrant evaluation](../backend/src/test/java/dev/arc/engine/expression/ExpressionCompatibilityTest.java), [request resolver contract](../backend/src/test/java/dev/arc/engine/MemoizingRuleResolverTest.java), [expired preparation stops later queries](../backend/src/test/java/dev/arc/rule/RuleExecutionServiceTest.java), [source deadline propagation](../backend/src/test/java/dev/arc/engine/execution/ParametersTest.java), [trace limits and expression deadline propagation](../backend/src/test/java/dev/arc/engine/execution/ExecutionTraceTest.java), [Formula calls, locations and shared budgets](../backend/src/test/java/dev/arc/engine/execution/FormulaCallExecutionTest.java) |
| Function help, arity and runtime support could drift after catalog splitting or fixture regeneration. | Keep evaluator dispatch and capability metadata aligned. Preserve every catalog field, ordering and accepted argument count during a refactor; change golden fixtures only for an intentional reviewed capability change. | [Catalog contracts](../backend/src/test/java/dev/arc/engine/expression/FunctionCatalogTest.java) |
| Separate executable/incomplete-graph validation paths could miss expression fields or fetch external data while diagnosing syntax. | Share node expression enumeration and keep draft shape distinct from executable validation. Add a new node kind across schema, scopes, evaluator, diagnostics, script parser/renderer and exhaustive frontend inspector together. Static checks may read source definitions, never source values. | [Validation contracts](../backend/src/test/java/dev/arc/engine/validation/ValidatorTest.java), [node code editing](../backend/src/test/java/dev/arc/engine/script/NodeEditorTest.java), [graph authoring](../frontend/tests/graph-authoring.spec.ts) |
| A node editor could accidentally acquire ownership of the containing graph or overwrite it after a failed build. | Keep graph/code transitions in one document. A node fragment replaces only its own node and outgoing edges, plus Input parameters when applicable; incoming edges, unrelated nodes and graph notes remain intact. Failed builds retain the prior graph and the editable text buffer. | [Node fragment ownership](../backend/src/test/java/dev/arc/engine/script/NodeEditorTest.java), [canonical script](../backend/src/test/java/dev/arc/engine/script/ArcScriptContractTest.java), [document transitions](../frontend/tests/unit/document.spec.ts) |
| Generic map merging could confuse sequential updates, mutually exclusive branches and concurrent sibling writes. | Preserve producer identity and branch-sensitive scope. Joins execute once, skipped branches do not block them, conflicting active sibling assignments fail, and one/multiple reached Outputs retain their existing result shapes, including null values. | [Fan-out and joins](../backend/src/test/java/dev/arc/engine/execution/FanOutTest.java), [graph contract](architecture.md) |
| Extracting services could move writes outside transactions or silently replace pinned configuration with the latest version. | Keep lock → revision check → validation → publication inside the write transaction. Preserve immutable pins and distinguish explicit null, missing values, caller overrides and fallback policy in every provider. Mock collaboration tests do not prove database atomicity. | [Rule commands](../backend/src/test/java/dev/arc/rule/RuleServiceTest.java), [source reads](../backend/src/test/java/dev/arc/source/SourceExecutionServiceTest.java), [parameters](../backend/src/test/java/dev/arc/engine/execution/ParametersTest.java), [real PostgreSQL HTTP checks](../scripts/smoke.py) |
| A shorter HTTP wrapper could drop constraints while appearing equivalent. | Retain the total deadline, connection/read timeouts, bounded response body and disabled redirects/retries; each constrains a different failure mode. Preserve parameter encoding and connection-time destination checks when replacing transport code. | [Provider contract](maintaining.md#backend-boundaries), [encoding, redirect and timeout tests](../backend/src/test/java/dev/arc/source/http/HttpSourceTest.java), [library assessment](reviews/2026-09-22-library-options.md) |
| Feature code collected in generic `components`/`utils`, and global CSS relocation could silently reorder overrides. | Keep page/controller/feature controls with their owner; shared controls must not import feature orchestration. Keep pure domain and HTTP modules independent of UI libraries. Preserve stylesheet cascade/import order and responsive overrides when splitting files. | [Frontend ownership](maintaining.md#frontend-boundaries), [architecture guard](../scripts/check_architecture.py), [routing geometry](../frontend/tests/routing.spec.ts), [responsive studio/source UI](../frontend/tests/studio.spec.ts) |

## Verification lessons

- Test user-visible effects. An invalid Save may reject at the command boundary rather than disable a button; assert the visible error, absence of the write and unchanged server revision. A test should not force a particular implementation of a valid behavior.
- Exercise late success **and** late failure, selection changes, close/reopen, retry and keyboard entry points when affected. An immediate happy-path test misses the schedules that caused the draft-loss defects.
- Use unique IDs and display names for fixtures selected by label. Re-running a suite against the same disposable database must not create ambiguous locators. Wait for observable layout completion before measuring or clicking an edge; arbitrary timing is not a contract.
- Use a clean Java build after package/class moves so stale compiled Spring beans cannot mask the real result. Remove obsolete imports, entry points and cross-test helper dependencies together with the move. `clean` removes compiled output, not obsolete `.java` files: restoring deleted main or test sources can still break compilation, and `spring-boot:run` also compiles tests. The native launcher reports untracked sources at paths deleted in available Git history; it preserves files and ordinary new sources. Inspect reported files and back up needed edits before moving obsolete copies outside the source directories. Coverage: [native startup diagnostics](../scripts/check_dev.test.mjs). See [startup troubleshooting](../README.md#troubleshooting-native-startup) for the distinction and history limitations.
- Use a separate Compose project, ports and database volume for tests that write fixtures. Clean up only that project. Do not validate against the user's working database.
- Distinguish static source assessment, unit behavior, real HTTP/database checks and browser workflows in the completion report. Do not claim a candidate library was exercised when it was only inspected, or that zero findings guarantees zero remaining bugs.
